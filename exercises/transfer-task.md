# 独立迁移任务：设备借用申请

[练习说明](../docs/practice.md) · [起始文件](starter.py)

面向校园小组的设备借用服务需要接收申请。重复点击、网络重发或重启后重试，都不能为同一次请求创建第二条记录。全部数据为虚构；本题不发送通知、不操作真实设备，也不实现审批。

## 交付接口

在自己的答案文件中实现：

```python
class LoanBook:
    def __init__(self, path: str): ...
    def reserve(self, tenant: str, key: str, payload: dict) -> dict: ...
```

`path` 是可信调用方指定的 SQLite 文件。构造器需要在空数据库中创建下表；重新构造不能清空历史。表名固定是为了让评分器进行故障注入与一致性核验，具体 SQL 写法自行决定。

| 表 | 必需字段与约束 |
| --- | --- |
| `requests` | `request_id` 整数主键；`tenant`、`asset_id`、`state` 非空文本；`days` 非空整数 |
| `idempotency` | `tenant`、`key`、`fingerprint` 非空文本；`request_id` 非空整数；`(tenant,key)` 唯一 |

`tenant` 和 `key` 必须是 1 至 64 位字符串，只能包含大小写英文字母、数字、下划线和短横线。它们都是可信本地调用上下文的参数；真实 HTTP 接口不能从用户随意填的 JSON 中决定租户。

`payload` 必须恰好包含 `asset_id`、`days`。设备编号为两个大写英文字母、短横线、三个数字，例如 `CA-001`；`days` 为 1 至 14 的真正整数，拒绝布尔值、字符串和小数。参数错误统一抛 `ValueError`，并且不能留下任何写入。

成功返回恰好四个字段，例如：

```json
{"request_id": 1, "asset_id": "CA-001", "days": 3, "state": "pending"}
```

主键应为正整数，由持久化存储确定，不要求从 1 连续增长。`pending` 只表示申请已记录。

## 必须满足的行为

1. 同租户、同键、相同参数，返回原申请；JSON 字段顺序不应影响判断。
2. 同租户、同键、不同参数，抛 `ValueError`，不能覆盖、创建新申请或悄悄返回旧结果。
3. 不同租户可使用相同键，得到不同申请；同租户的新键也代表一次新的申请。
4. 重新构造对象或重新连接数据库后，仍能重放原结果。
5. 多线程对同一个对象并发重放相同请求，只留下一个申请和一个幂等记录。
6. 申请与幂等记录必须一起提交。若插入幂等记录时数据库失败，申请也要回滚；保留并向调用方抛出原始 `sqlite3.DatabaseError`。

评分器会安装一个使幂等记录插入失败的 SQLite 触发器，验证第六项。不要捕获所有异常后假装成功，也不要删除数据库触发器。

## 本题的边界

申请不会扣减库存，因此无需实现设备剩余量。本地数据库的原子性不涵盖外部邮件、支付或设备控制。没有认证服务、跨进程压力测试或跨区域复制；不要把这道题描述为完整生产系统。
