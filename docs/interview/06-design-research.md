# 51–60：系统设计与研究判断

[题库目录](README.md) · [上一组](05-evaluation.md) · [模拟面试](mock-interviews.md)

## 51. 设计一个企业知识与工单助手，你先问什么？〔中阶〕

**直接回答：** 明确用户、资料范围、读写权限、工单副作用、数据规模、延迟与成本目标，以及哪些结果必须人工确认，再选择架构。

**理由与取舍：** 如果任务只是查制度，检索与引用已足够；创建工单则增加认证、审批、幂等与恢复。先画业务边界，再画模型和服务，能避免为不存在的需求堆组件。完整练习见 [毕业级综合项目](../projects/capstone.md)。

**追问／得分点：** 面试官拒绝给具体流量时，应怎样提出明确的估算假设并继续设计？

## 52. 单 Agent、多 Agent 与固定工作流如何选择？〔中阶〕

**直接回答：** 根据任务可分解程度、信息依赖、责任边界和评测结果选择。路径稳定的任务优先工作流；需要动态选择动作时评估单 Agent；独立专业子任务有明确收益时再考虑多 Agent。

**理由与取舍：** 多 Agent 增加协调、上下文传递和冲突处理成本。同一个模型重复讨论也不保证错误独立。应在相同预算下比较成功率、时延与失败轨迹，并明确谁有最终写入权限。

**追问／得分点：** 给出一个并行研究任务适合多 Agent 的理由，再给出一个退款流程不适合自由协商的理由。

## 53. 如何为 Agent 服务做容量估算？〔进阶〕

**直接回答：** 从到达率、平均任务时间、任务内模型调用数、工具并发和供应商配额出发估计在途任务与瓶颈，再用负载测试校准。

**理由与取舍：** 稳定系统可用 Little's Law 做粗估：在途量约等于到达率乘平均停留时间。例如每秒 2 个任务、平均 10 秒，约 20 个任务在途；这不是 p95 容量保证。重试、突发流量和长任务会进一步放大需求。

**追问／得分点：** 为什么限制 HTTP 请求并发仍可能挡不住每个任务内部的工具调用洪峰？

## 54. 哪些结果可以缓存？〔中阶〕

**直接回答：** 在权限、资料版本和有效期均可确定时，缓存检索结果或只读工具结果；缓存键至少包含影响结果的输入、租户、权限版本和数据版本。

**理由与取舍：** 只按问题文本缓存会让不同租户共享不该共享的答案。易变状态需要较短有效期或事件失效；写操作结果的幂等记录和普通性能缓存承担不同职责，不能随意淘汰后假定仍能防重复。

**追问／得分点：** 用户撤销访问权限后，旧缓存如何保证不再返回受限文档？

## 55. 流式输出与长任务 API 应怎么设计？〔进阶〕

**直接回答：** 任务提交返回稳定的 run_id，状态查询与事件流围绕同一任务；事件有单调序号，客户端可以断线重连。写操作完成状态以服务端提交记录为准。

**理由与取舍：** 用户看到“正在创建”只是进度，不能当作创建成功。取消请求也可能赶不上已提交的副作用，因此要返回取消结果和已完成动作。长任务需要持久化，不能把 HTTP 连接存活当作任务生命周期。

**追问／得分点：** SSE 断开后客户端如何续读，怎样避免重复显示或误触发业务动作？

## 56. 在知识库中发现相互冲突的政策怎么办？〔中阶〕

**直接回答：** 根据权威级别、适用范围、生效时间和版本规则处理；规则不足时展示冲突并要求澄清，不靠模型投票决定哪条是真的。

**理由与取舍：** 最近上传不等于最近生效；相同标题也可能适用于不同地区或用户。索引元数据必须保留这些条件，回答引用具体版本。将冲突样本加入评测，验证系统不会挑一条最方便的规则。

**追问／得分点：** 一份旧文档包含未来生效条款，时间过滤应看上传日期还是生效日期？

## 57. 阅读一篇 Agent 论文应抓住什么？〔中阶〕

**直接回答：** 明确研究问题、核心假设、方法相对基线改变了什么、实验预算、任务与数据、评价规则，以及结论适用范围。

**理由与取舍：** 更高分可能来自更强底模、更多 token 或更有利的工具。把方法拆成可复现的组件，检查消融、方差、失败案例与代码可用性。论文中一个 benchmark 的结果不能直接外推到自己的业务。

**追问／得分点：** 作者只报告最佳种子，缺少重复运行，你会怎样描述这条结论的可信度？

## 58. 为什么 Agent benchmark 结果不一定能迁移？〔进阶〕

**直接回答：** 任务分布、工具接口、用户行为、权限约束和评价标准不同，都会影响表现。公开榜单只是特定实验条件下的观察。

**理由与取舍：** 模拟用户可能很配合，而真人经常省略条件；静态网页和动态业务状态也不同。先用目标场景的小型标注集验证，再逐步扩大范围。对执行型任务，检查最终状态与过程约束，不能只比较文本相似度。

**追问／得分点：** 如何把公开任务改造成内部回归集，又避免仅重现原 benchmark 的偏差？

## 59. 如何提出一个可做的本科 Agent 研究问题？〔进阶〕

**直接回答：** 选择一个边界清楚的失败现象，提出可证伪假设，设计简单基线、对照变量和可复现评测。例如“证据压缩是否在固定 token 预算下提高多跳问题的完整证据覆盖率”。

**理由与取舍：** “做一个更聪明的 Agent”无法检验。研究可以先用小规模公开或合成资料，把贡献限定在具体机制；负结果也有价值，只要实验能排除明显混杂因素并说明成本。

**追问／得分点：** 为上述问题列出自变量、因变量、控制变量和一个可能推翻假设的结果。

## 60. 怎样证明简历里的项目是你理解并完成的？〔入门〕

**直接回答：** 能从需求讲到实现，展示一个关键路径、一个失败案例、一项有基线的实测结论，以及自己做出的取舍和未完成边界。

**理由与取舍：** 框架名和截图难以证明能力。面试官更容易追问为什么选择某种事务、怎样处理参数错误、指标来自多少样本。没有真实流量就写合成数据；没测过吞吐就不写“高并发”。

**追问／得分点：** 用 90 秒讲项目，再用代码或测试定位其中一句话的证据。参考 [答辩模板](portfolio.md)。
