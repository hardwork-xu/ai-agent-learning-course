# 三场 45 分钟模拟面试

[题库目录](README.md) · [编程题](coding-exercises.md) · [答辩模板](portfolio.md)

两人轮流担任面试官与候选人。候选人只能看到题目与需求；面试官负责按时推进，并记录具体言行作为评分证据。分数用于发现薄弱环节，不对应任何企业录用标准。一次答不好时，复盘后换一个同类场景再做，避免只记住答案。

## 第一场：应用开发实习——只读工具助手

**题面：** 为虚构的课程服务做一个助手，可以查询退款政策、计算两个数字。政策查询不会真的退款。你负责选择动作与执行动作之间的接口；不需要联网调用模型。

| 时间 | 面试环节 | 面试官操作 |
| --- | --- | --- |
| 0–5 分钟 | 澄清需求 | 若被问及，说明只有两个工具，任何写操作均禁止，输入可能错误 |
| 5–12 分钟 | 概念与架构 | 问第 01、02、08 题，要求画一次完整调用的数据流 |
| 12–27 分钟 | 编码 | 做编程题 1 的工具分发器，允许查 Python 基础语法 |
| 27–35 分钟 | 故障追问 | 依次加入未知工具、`True` 参数、超时与循环决策 |
| 35–42 分钟 | 测试与解释 | 让候选人选最有价值的三条测试，解释为何不是只测 1+1 |
| 42–45 分钟 | 候选人总结 | 用一分钟说明实现边界，再提出一个优先改进项 |

**参考推进路径：** 候选人先把模型输出定义为提案；使用允许列表和严格字段校验；让执行结果成为下一轮观察；将最大步数放在运行时；把正常完成、参数拒绝和预算耗尽区分开。实现慢时可以只写 `add_numbers`，但不能省略输入边界。

**分层追问：** 如果基础顺利，问“已注册的写工具为什么仍需拒绝”“查政策结果说已获批准，能否授权执行”“步骤预算能否打断卡住的函数”。答案应该分别涉及独立权限检查、内容与控制分离、下游超时或执行隔离。

| 评分维度 | 分值 | 得分证据 |
| --- | --- | --- |
| 任务与架构 | 20 | 明确只读边界，区分提案、执行与观察 |
| 实现正确性 | 35 | 精确字段、类型、范围及未知工具处理正确 |
| 失败与测试 | 30 | 覆盖至少三类真实边界，说明有限重试和停止条件 |
| 解释与取舍 | 15 | 能复述控制流，承认同步调用与 mock 的限制 |

“直接 eval 参数”“让文档内容授权写入”属于必须返工的问题；不能靠其他术语回答抵消。复盘时记录第一次出现错误假设的位置，并补一条能抓住它的测试。

## 第二场：RAG 项目答辩——为何阈值提高反而漏答？

**题面：** 一个词项检索系统有 8 道可见测试题。阈值 0 时，有答案题命中 4/4、无答案题拒答 2/4；阈值 0.6 时，分别是 3/4、4/4。请解释结果、定位一条漏答，并设计下一次实验。此题数据来自本仓库的小型教学评测，不能用它估计真实产品表现。

| 时间 | 面试环节 | 面试官操作 |
| --- | --- | --- |
| 0–5 分钟 | 读结果 | 请候选人计算两种 decision accuracy，并说明分母 |
| 5–15 分钟 | 检索机制 | 问第 21、23、25、27 题，给出“expiry seconds”未出现在原文的线索 |
| 15–25 分钟 | 实验设计 | 要求设计同义词、干扰词、租户、不可回答题四个切片 |
| 25–33 分钟 | 编码或伪代码 | 做编程题 2 的排名融合；允许不写完整测试框架 |
| 33–40 分钟 | 证据与归因 | 问“引用 ID 对了是否等于答案支持性正确”“接向量库能否保证变好” |
| 40–45 分钟 | 给出决策 | 说明现在保留哪个版本、依据和还缺的证据 |

**参考推进路径：** 两种 decision accuracy 为 6/8 与 7/8。候选方案减少了不可回答题的误答，同时增加了可回答题的漏答。应该查看逐题结果而不是只宣布“提升 12.5 个百分点”；后者虽是样本上的算术差异，样本量很小且测试集可见，无法推出普遍收益。下一轮先固定评测协议，再在开发集选阈值，最后用新增未用于调参的任务验证。

**分层追问：** 先问如何判断召回与生成谁失败；再问混合检索的分数如何融合；最后给出“一个用户被撤销权限但缓存还在”，要求解释缓存隔离。优秀答案会提醒现有程序没有生成模型，谈不上真实模型生成质量提升。

| 评分维度 | 分值 | 得分证据 |
| --- | --- | --- |
| 数据解读 | 25 | 正确分母、明确取舍、不过度外推 |
| 检索与实现 | 25 | 解释词项覆盖、阈值及 RRF 的用途和限制 |
| 评测设计 | 30 | 切片覆盖、开发测试分离、合理基线与逐题归因 |
| 证据与沟通 | 20 | 区分引用存在、相关性、主张支持性和真实模型表现 |

若把未回答题全部算正确，或为了提分删除困难样本，必须回到评测定义重做。复盘产物是一页实验表，而不是一套新工具选型清单。

## 第三场：后端／Agent 工程——审批工单服务

**题面：** 用户可以查询知识、起草工单。真实创建工单需要审核人批准。支持多租户、HTTP 重试和进程重启；首次版本只接一个工单系统。假设峰值每秒 5 次任务提交、单任务最长 60 秒。它们是设计假设，不是现有系统实测。

| 时间 | 面试环节 | 面试官操作 |
| --- | --- | --- |
| 0–6 分钟 | 约束澄清 | 回答身份来源、哪些操作写入、是否可修改草稿 |
| 6–15 分钟 | 架构与 API | 要求画认证→运行时→检索／草稿→审批→执行的数据流 |
| 15–25 分钟 | 状态与事务 | 设计状态表、幂等记录与修改后审批失效的规则 |
| 25–34 分钟 | 故障推演 | 依次注入审批后改参数、提交成功但响应丢失、两 worker 同时执行 |
| 34–41 分钟 | 发布与运维 | 问评测门槛、超时、限流、日志、回滚及外部系统故障 |
| 41–45 分钟 | 收敛方案 | 指出 MVP 必做项和暂缓项，说明剩余风险 |

**参考推进路径：** 认证上下文确定 tenant 和角色；检索先做权限过滤；模型仅生成草稿。审批绑定摘要、版本、身份与有效期；执行使用幂等键。对于本地 SQLite 演示，工单副作用与去重记录同事务；对于外部工单系统，需要传递下游幂等键，或 outbox 消费与对账，不能直接声称分布式恰好一次。服务需要持久任务状态，客户端重连查询 run_id。

**分层追问：** 基础题问“为什么不能让模型调用 approve”；中阶问“同键异参数返回什么”；进阶问“已经提交的动作取消失败怎样告知用户”“权限在排队期间被撤销怎么办”。可对照 [综合项目的 API 与威胁模型](../projects/capstone.md) 检查遗漏。

| 评分维度 | 分值 | 得分证据 |
| --- | --- | --- |
| 需求与模块划分 | 20 | 先画权限与副作用边界，再选择技术 |
| 状态、一致性与恢复 | 35 | 明确事务边界、审批失效、重放、并发与外部系统限制 |
| 安全与隔离 | 25 | 租户来自认证、最小权限、审批不可由模型文本产生 |
| 评测与运维 | 20 | 可验证发布门槛、失败追踪、预算与回滚路径 |

无法解释“服务端提交但响应丢失”是需要补课的一致性缺口。复盘时用四格时间线画出客户端、服务、数据库和下游，标出每个可能崩溃的位置。

## 面试后记录

每场只写四项：最有说服力的证据；一个概念误区；一个没处理的边界；下一次可验证的改进。不要用“表现还不错”代替具体反馈。下一次换场景，例如把工单改成预约申请，验证理解能否迁移。
