# 通用 CS：把 Agent 项目接回计算机基础

[面试目录](README.md) · [岗位映射](../job-readiness.md) · [先修补课](../prerequisites.md)

先用下面的问题找短板。每题先独立写或画，再看提示；耗时只是记录，不作为所有人的统一合格线。这里是诊断与复习入口，不替代完整算法、网络或数据库课程。

## 1. 数据结构与复杂度

**任务：** 收到 `[(doc_id, score), ...]`，同一文档可能重复。保留每个 ID 的最大分数，按分数降序、ID 升序返回前 k 项。解释 n 条输入和 m 个不同 ID 时的复杂度，再讨论 k 远小于 m 时的方案。测试 k=0、重复、并列和非法 k；先说明是否允许 NaN。

<details>
<summary>完成后核对思路</summary>

用字典合并是期望 O(n)，全排序是 O(m log m)，空间 O(m)。使用大小 k 的堆可以将选择部分降为 O(m log k)，但需要仔细处理相同分数的排序规则；最后输出仍需排序。复杂度和正确性分开解释。不要用重复遍历整个列表的办法隐藏 O(n²)。

</details>

## 2. 网络与重试

**任务：** 提交工单超时了，客户端不知道服务端是否已经写入。画出“请求未到达”“写入后响应丢失”两种时间线。什么时候可以重试？重试参数、幂等键与总预算如何变化？

<details>
<summary>完成后核对思路</summary>

超时不等于未执行。沿用原业务幂等键，保持同一请求内容，必要时查询原结果；不要超时就生成新键。重试次数、单次超时和总时限分别约束。HTTP 的方法语义不能自动保证自定义 POST 的业务幂等。练习用项目的 outbox 故障演练验证“效果发生、回执未保存”。

</details>

## 3. 数据库与并发

**任务：** 两个连接同时检查“工单不存在”，然后插入。只在 Python 里先查再写为什么不足？给出一条唯一约束和事务方案；解释进程锁能否覆盖两个进程。

<details>
<summary>完成后核对思路</summary>

检查与插入之间可能交错。将业务键设为数据库唯一约束，在事务中写业务记录及去重记录，冲突时校验请求摘要并读取稳定结果。进程内锁不跨进程，也不解决崩溃后的状态。数据库内原子性不能自动跨越外部工单服务。

</details>

## 4. 操作系统与服务资源

**任务：** 一个外部模型请求阻塞 30 秒；服务同时来了 100 个请求。单线程、每请求线程、有限工作池各有什么表现？连接超时、读取超时、请求截止时间有什么区别？

<details>
<summary>完成后核对思路</summary>

单线程容易排队；无限创建线程会耗尽资源；有限池需要队列上限、过载响应和取消策略。socket timeout 通常约束一次阻塞 I/O，不必然限制整个请求总时长。必须测量等待时间与执行时间，不能把“设置了 timeout”当成端到端期限证明。

</details>

## 5. 接口设计与测试

**任务：** 审核人看了版本 2，点击批准之前编辑者改成版本 3。设计请求字段、错误响应和并发测试。再描述改变 payload 后旧幂等键应返回什么。

<details>
<summary>完成后核对思路</summary>

提交审核人实际看过的 version 与 digest，服务端在同一事务中比较当前值，不相符时要求重新查看。摘要不能作为身份凭据。相同幂等键对应不同内容时返回冲突；不要静默执行新内容。测试要制造读取与批准间的交错，而非只测试先批准再编辑。

</details>
