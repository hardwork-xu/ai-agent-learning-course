# 面试：把概念讲成可以验证的工程判断

[返回项目首页](../../README.md) · [实战项目](../projects/README.md)

这套题面向准备实习与初级岗位的 CS 学生，也包含供进阶训练使用的系统设计与研究题。共 **60 道讨论题、4 道有完整参考实现的编程题、3 场 45 分钟模拟面试**。它不是某家公司的题库，题目难度不代表企业职级。

## 怎样练习

先用 60–90 秒口头回答，再展开一个具体例子。每题答案都给出结论、取舍和追问；不要求逐字背诵。回答“用某个框架解决”之后，必须继续解释数据流、状态和失败路径。

统一按 0–3 分自评：0 分为概念错误；1 分为结论大致正确但缺少机制；2 分能说明机制和具体失败场景；3 分还能提出可验证的取舍或实验。不要把“提到了很多术语”算作完整回答。

- 时间有限：先做 01、02、11、13、14、21、26、31、34、41、44、51，再完成一个实战项目。
- 面试前一周：每天选 6 题，录音复述；对照答案只补证据不足的部分。
- 项目完成后：用 [项目答辩与简历模板](portfolio.md) 把代码、测试和结论连起来。
- 两人练习：按 [模拟面试](mock-interviews.md) 的节奏提问，不提前把评分点念给候选人。
- 编程练习：先独立写 [4 道编程题](coding-exercises.md)，再看参考实现和边界条件。

## 回答时容易失分的表达

“RAG 消除了幻觉”“加了审批就安全”“重试三次一定能成功”“零温度就完全确定”“多 Agent 一定优于单 Agent”，都把条件结论说成了普遍保证。更好的回答是：说明目标与约束，指出失败方式，给出如何检测和控制失败的方案。

资料中的运行结果只证明对应环境和案例下的行为。离线 mock 通过，不等于真实模型表现通过；学习项目没有真实用户，就直接说明是合成任务评测。
