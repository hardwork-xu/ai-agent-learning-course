# 21–30：RAG 与上下文

[题库目录](README.md) · [上一组](02-tools-runtime.md) · [下一组](04-reliability-security.md)

## 21. RAG 的完整数据流是什么？〔入门〕

**直接回答：** 离线侧整理文档、切分、建立索引；在线侧处理问题、检索候选、过滤和排序、构造上下文、生成或提取答案，并返回能追溯到原文的证据。

**理由与取舍：** 现代工程中 RAG 常泛指检索增强流程；[原始 RAG 论文](https://arxiv.org/abs/2005.11401)研究了参数化生成器与非参数记忆的结合。实现中必须分别评测检索和回答，否则无法知道缺证据还是用错证据。

**追问／得分点：** 如果正确文档根本没进入 top-k，为什么换生成提示词通常不是首要修复？

## 22. Chunk 越大或越小分别有什么问题？〔入门〕

**直接回答：** 小片段更聚焦，但可能切断条件和定义；大片段保留上下文，却容易混入噪声、占用预算。切分应优先利用标题、段落、表格与文档结构。

**理由与取舍：** 一条退货规则中的期限、例外和适用范围分在不同块时，检索命中一块仍可能答错。可以保留父文档关系，检索小块后扩展邻近上下文。重叠会增加索引体积，并可能让评测重复计数。

**追问／得分点：** 如何为表格、代码和政策条款分别设计切分策略，而不是统一按字符截断？

## 23. 关键词检索与向量检索如何选择？〔中阶〕

**直接回答：** 关键词检索适合精确术语、编号和罕见实体；向量检索适合同义表达和语义相近的问题。混合检索是可测试的候选方案，而非默认最优解。

**理由与取舍：** 用户问错误码 `E104` 时，近义表达不如精确匹配重要；问“怎么让别人帮我办”时，语义检索可能更容易找到“委托办理”。比较相同查询集上的召回、延迟和成本，再决定是否增加一种检索器。

**追问／得分点：** 当两种检索分数不可直接比较时，怎样融合排名？参考 [编程题 2](coding-exercises.md)。

## 24. Reranker 能修复哪些问题？〔中阶〕

**直接回答：** Reranker 对已有候选重新排序，常用于减少无关候选进入上下文。它无法找回第一阶段完全没有召回的文档。

**理由与取舍：** 候选越多，潜在召回越好，但重排成本也越高。要一起观察第一阶段 Recall@k、重排后的排序质量和最终答案质量。只有最终准确率上升且额外延迟可接受时，组件才有价值。

**追问／得分点：** 为什么“增加 reranker 后结果不变”可能是召回瓶颈，也可能是数据集太简单？

## 25. Recall@k 与 MRR 反映什么？〔中阶〕

**直接回答：** Recall@k 衡量已标注相关文档有多少进入前 k 个结果；MRR 对每个查询取第一个相关结果排名的倒数，再对查询平均。两者衡量检索排序，不直接等于回答正确率。

**理由与取舍：** 多跳问题需要两份证据时，只把第一份排在首位可让 MRR 很好，却仍无法回答。必须明确标注粒度、去重方式、无相关文档查询的处理规则，并补充“全部必需证据被召回”的指标。

**追问／得分点：** 正确证据在第 2 与第 8 位，top-5 场景为什么不能仅用 MRR 判断任务可解？

## 26. 有引用的答案为什么仍可能错误？〔入门〕

**直接回答：** 引用可能确实存在，却不支持那条结论，也可能过期、被截断或适用对象不同。引用存在性、证据支持性和答案正确性需要分别检查。

**理由与取舍：** 原文说“工作日内处理”，答案说“任何日期都当天处理”，附上链接也不能补救。把答案拆成可核查的主张，再检查每项主张与片段的关系；严格场景优先直接提取并保留限定词。

**追问／得分点：** 如何自动检测不存在的 citation ID？哪些支持性判断仍需要人工或经过校准的评审？

## 27. RAG 应该什么时候拒答？〔中阶〕

**直接回答：** 没有足够相关且有权限使用的证据、证据相互冲突、问题要求超出资料范围，或关键条件缺失时，应该拒答或澄清。

**理由与取舍：** 检索分数不是正确概率；阈值应在有答案与无答案样本上联合调试。拒答太多会损害可用性，答得太多会增加错误。分别报告可回答问题的正确率和不可回答问题的错误作答率。

**追问／得分点：** 用户问“能否退款”而规则依赖购买日期，应该拒答、澄清还是猜测？

## 28. 多租户 RAG 如何避免跨租户泄漏？〔进阶〕

**直接回答：** 查询必须携带来自认证上下文的租户和权限；检索层按权限限制候选，生成前再次检查文档授权。缓存、日志和导出也要保留相同隔离边界。

**理由与取舍：** 不能让模型从问题文本里自行决定 tenant_id。仅在生成后删除敏感句子太晚，因为不该读取的内容已经进入上下文。权限更新后还要使旧缓存失效，防止撤权后的历史结果复用。

**追问／得分点：** 如果向量数据库只支持有限过滤，应该怎样选择索引隔离策略？

## 29. 长上下文能否替代检索？〔中阶〕

**直接回答：** 某些小语料任务可以直接放入完整材料，但窗口大不等于模型能稳定利用所有位置的信息。选择应基于资料规模、更新频率、权限和目标任务评测。

**理由与取舍：** [Lost in the Middle](https://arxiv.org/abs/2307.03172)在其测试模型和任务上观察到信息位置会影响表现；这不是所有新模型的固定结论。可做位置置换与干扰文档实验，同时比较 token、延迟与答案支持率。

**追问／得分点：** 怎样设计实验，区分“模型不会用材料”和“检索没找到材料”？

## 30. Agent memory 应该保存什么？〔中阶〕

**直接回答：** 保存对后续任务确实有用、来源清楚、获准保留的信息，例如已确认偏好、任务状态和经过验证的事实；同时记录作用域、时间、来源和失效规则。

**理由与取舍：** 聊天历史不是全部都值得写入长期记忆。错误摘要和恶意网页可能污染后续任务。写入前做可信度与权限检查，读取时区分事实、偏好和暂时假设，并支持更正和删除。

**追问／得分点：** 昨天的工具故障应长期记为“服务永远不可用”吗？如何表示时效性？
