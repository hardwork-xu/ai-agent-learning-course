## 题 1：实现严格的工具分发器

**输入：** 一个包含 `name` 与 `arguments` 的字典。唯一允许的工具为 `add_numbers`，参数必须恰好为 `a`、`b`，值为整数或有限浮点数，绝对值不超过 `10**12`。结果也必须在同样范围内。

**输出：** `{"result": 数值}`；其他输入一律抛 `InvalidCall`，不能执行动态代码、自动转换字符串或忽略未知字段。

**考查点：** 把 schema、类型校验和业务范围区分开；特别注意 `bool`、NaN、无穷与超大整数。`eval`、按字符串任意查找函数、只校验一部分字段均不合题意。

[完整参考答案](exercises/01_dispatch.py)先验证信封和参数，再计算并检查结果。固定字段下时间和额外空间为 O(1)；不计任意精度整数解析本身的成本。真实 API 还需要限制请求体大小。

```bash
python docs/interview/exercises/01_dispatch.py
```

测试覆盖正常负数小数、布尔值、非数值、非有限浮点数、超大整数、未知字段、未知工具、缺字段和结果越界。**追问：** 如果将 `add_numbers` 换成“修改地址”，哪些检查必须在执行层新增？

## 题 2：融合两个检索器的排名

**输入：** 多组按相关性排序的文档 ID、非负常数 c 与输出上限 k。每个检索器对文档 d 的贡献为 `1 / (c + rank(d))`，排名从 1 开始。

**要求：** 单个排名内重复文档只能贡献第一次出现的分数；不同检索器的贡献累加；同分按文档 ID 字典序排列；空输入和 k=0 返回空列表。这里保留原始列表的排名位置，重复项之后的文档不会向前补位。

[完整参考答案](exercises/02_rrf.py)实现 Reciprocal Rank Fusion 的这个明确变体。若各列表共 N 项、去重后有 U 个文档，复杂度为 O(N + U log U)，空间为 O(U) 加单列表去重集合。大规模 top-k 可以考虑堆，但先确认排序真是瓶颈。

```bash
python docs/interview/exercises/02_rrf.py
```

测试覆盖跨检索器累加、重复文档、稳定同分、空集、零上限和非法参数。**追问：** 这种融合不使用原始分数，损失什么信息？怎样用相同查询集比较 RRF、加权分数和单检索器？

## 题 3：有总体预算的有限重试

**输入：** `operation(remaining_seconds)`、单调时钟、睡眠函数、总时间预算、最大尝试次数和退避间隔。只允许 `TransientError` 重试；其他异常立即上抛。

**要求：** 每次尝试消耗同一个总体预算；等待会耗时；预算为零时不调用操作；用假的时钟和睡眠测试，不让测试真的等待。返回太晚的“成功”不能算按时完成。

[完整参考答案](exercises/03_retry.py)采用封顶的指数退避。为了让基础题的预期时间可直接检查，参考实现不加抖动；多人客户端生产扩展应注入随机源并测试抖动边界。其重试机制不能强行打断一个卡住的同步函数，因此 `operation` 必须给真正的 HTTP 或数据库调用设置超时。

```bash
python docs/interview/exercises/03_retry.py
```

测试覆盖暂时失败后成功、永久错误不重试、尝试耗尽、无预算和迟到结果。时间复杂度为 O(A) 次控制操作，A 为尝试次数；等待时间与下游执行时间另计。**追问：** 若 operation 已经提交写入却超时，为什么此函数不能独自保证安全重试？

## 题 4：带租户作用域的事务幂等

**输入：** SQLite 路径、租户、幂等键和只含 `title` 的工单参数。输出工单 ID 与状态。

**要求：** 同租户同键同参数重放原结果；同键不同参数拒绝；不同租户相同键互不影响；并发的相同请求只创建一张本地工单；副作用和结果记录在同一事务提交。

[完整参考答案](exercises/04_idempotency.py)使用规范化 JSON 的摘要及 `(tenant, key)` 唯一键，借助 `BEGIN IMMEDIATE` 把检查、插入工单和保存结果放进本地写事务。SQLite 在该模式下提前尝试获得写事务；高并发时仍可能因等待超时产生 busy 错误，必须按服务契约处理。[SQLite 事务文档](https://www.sqlite.org/lang_transaction.html)

```bash
python docs/interview/exercises/04_idempotency.py
```

测试验证重连重放、异参数冲突、租户作用域和 8 个线程并发重放。索引查找通常为 O(log R)，R 为记录数；写事务串行化是该教学实现的吞吐限制。

**边界：** 租户参数在本题中由调用者传入，尚无认证；上线时必须从已认证上下文派生。数据库内的原子性不覆盖外部邮件或支付，本题不能证明跨服务恰好一次。

**追问：** 在事务里发送邮件后连接断开，会出现什么？设计一个 outbox 表并解释为什么消费端仍需幂等。
