# 项目 02：有证据才回答的检索实验

[项目目录](README.md) · [上一项目](01-tool-agent.md) · [下一项目](03-durable-workflow.md)

**目标：** 用透明的检索基线理解证据、拒答和权限过滤，建立第一次有分母、保留失败样本的评测。CLI 名称为 `rag`，当前实现是词项检索加原文提取，没有生成模型；它是学习检索增强系统的起点。

## 第一步：观察命中与拒答

```bash
python -m agentlab demo rag
python -m agentlab evaluate --output work/evaluation.json
```

第一条命令回答虚构退款政策问题，并对混入无关主题的问题拒答。返回的 `citations` 是语料文档 ID，`abstained` 表示未作答。第二条命令比较阈值 0 与 0.6，打印逐题结果并保存 JSON。

## 第二步：理解检索公式和边界

阅读 [retrieval.py](../../src/agentlab/retrieval.py)、[语料](../../src/agentlab/fixtures/corpus.json)和 [题集](../../src/agentlab/fixtures/evaluation.json)。

```text
query → 英文小写词项集合 → 去停用词
      → 按可信 tenant 过滤文档
      → score = |查询词项 ∩ 文档词项| / |查询词项|
      → 阈值过滤与排序 → 取 top-1 原文并附 document ID
      → 无证据时拒答
```

重复词不增加权重；相同分数按文档 ID 排序。租户过滤发生在排名之前。分词器只识别 ASCII 字母和数字；直接拿它处理中文不会获得合理中文分词，这是一项明确限制。

阈值不是正确概率。它只表示查询词项中有多少比例出现在文档里；不同问题长度、同义词与噪声都影响它。当前答案引用整段原文，未实现 claim-level 支持性校验。

## 第三步：复现一个真实取舍

当前可见 test split 共 8 题；另外 4 题标为 dev，但阈值 0.6 是教学选择，没有自动调参过程。

| 指标 | 阈值 0 | 阈值 0.6 | 解释 |
| --- | --- | --- | --- |
| 可回答题 top-1 命中 | 4/4 | 3/4 | 严格阈值漏掉一题 |
| 不可回答题拒答 | 2/4 | 4/4 | 严格阈值减少错误作答 |
| 正确决策 | 6/8 | 7/8 | 只说明这 8 题的选择结果 |
| 回答覆盖率 | 6/8 | 3/8 | 质量提高可能伴随覆盖下降 |

打开 q08：`password reset expiry seconds`。文档有 `password reset`，但使用 `valid for fifteen minutes` 表达有效期；查询覆盖分为 2/4=0.5，达不到 0.6。这个案例用于说明词面限制，不能为了让报表好看而删除。

评测中的 `citation_precision_answered` 只检查返回的文档 ID 是否属于标注相关集合，不检查每条生成主张的真实性。仓库保留了这一指标的具体定义，避免把它简写成“事实准确率”。

## 第四步：故障实验

```bash
python -m unittest discover -s tests -p 'test_retrieval.py' -v
```

先看 `test_lexical_synonym_failure_is_visible`；再换成 `tenant="unknown-campus"`，确认无法读取其他租户的命中文档。只包含停用词的问题应该拒答，不能出现除零错误。相关测试分别为 `test_tenant_is_filtered_before_ranking` 与 `test_miss_and_stopwords_abstain`。

再手工增加三种合成情况到你自己的开发集：同义表达、表面词重合但实际无答案、两条规则相互冲突。现有提取器不会自动解决冲突；如果要支持它，先设计版本和适用范围元数据，再增加明确判定规则。新增实验数据不要回填到已用于比较的固定测试集后继续宣称是未见测试。

## 基线与验收

基线为阈值 0 的同一检索器，候选仅改变阈值，其他条件相同。验收要求：解释每个指标分母；复现 q08 的漏答；证明租户过滤在输出前生效；保留完整逐题结果和配置散列；写出严格阈值带来的收益与代价。

8 道可见测试不足以证明普遍效果，也不是隐藏 benchmark；这份实验的价值在于能复现、能解释、能发现限制。

## 扩展为生成式 RAG

**本基础实验未实现：** 中文处理、BM25、embedding、向量索引、混合检索、reranker、生成式回答与文档更新流水线。下一阶段 [项目 04](04-chinese-rag.md) 已提供中文词项、BM25、版本资料、逐题评测和可选本地生成草稿；向量检索、reranker 与生产资料流水线仍需独立扩展。

建议一次只改一个变量：先比较新的检索器能否找回 q08 这类同义问题；再比较固定候选集合下的重排；最后接生成器。生成器应只接收获准材料，并返回答案与 citation IDs；确定性程序检查 ID 存在，人工或校准后的评审检查证据是否支持主张。

真实模型需要自己的固定评测集、调用预算和错误分析，不能借用离线提取结果宣称模型达到同样质量。详细数据协议见 [评测数据集设计](evaluation-dataset.md)。

**答辩问题：** 为什么提高阈值减少误答但增加漏答？为什么引用正确文档仍不保证生成结论正确？若接向量库，哪些指标应该保持不变以便公平比较？
