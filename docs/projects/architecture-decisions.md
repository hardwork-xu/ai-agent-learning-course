# 三个 ADR：把选择和证据写下来

[项目目录](README.md) · [综合项目](capstone.md)

ADR（Architecture Decision Record）记录一个重要决定及其理由。先写约束与备选方案，再写选择；后续发现证据不支持时，新建替代记录并关联旧记录，不悄悄改写历史。本页提供三个可复制模板及与学习项目一致的示例。

## ADR 001：谁决定任务路径？

### 可复制模板

```text
标题：选择［固定工作流／单 Agent／多 Agent］处理［任务］
状态：提议／已接受／被 ADR-xxx 替代
上下文：用户、任务分布、副作用、延迟与预算约束。
备选：至少两种方案；各自的复杂度、失败方式与验证成本。
决定：采用哪种方案，哪些动作仍由确定性代码决定？
理由：来自现有数据的证据；尚无证据的假设单独标注。
后果：新增的维护成本、限制和退出条件。
验证：基线、任务切片、预算和失败测试。
重新考虑条件：什么可观测结果会让团队改变选择？
```

### 已写示例：审批采用固定工作流

**状态：** 已接受于本地教学实现；服务扩展仍需验证。

**上下文：** 创建工单必须先有合法草稿和针对该版本的审批，路径稳定，副作用不可由自由文本授权。

**备选：** 自由规划 Agent 决定何时批准；固定状态机；多个角色 Agent 协商批准。后两种“批准”若来自模型角色扮演，都不能代替真实授权。

**决定：** 将创建、修改、批准、执行写成固定状态转移；模型可参与草稿生成，但不接触 `approve` 权限。

**理由：** 约束主要来自业务状态与身份，可用代码直接表达；自由规划不会增加审批本身的合法性。现有测试验证未批准、过期、改参数、重放等路径，而不是验证模型是否愿意遵守指令。

**后果：** 新业务动作需要显式增加状态与测试；复杂非结构化调查暂不支持。能够清楚说明一次拒绝发生在哪个状态条件上。

**验证：** 运行 workflow 测试，逐个检查数据库副作用。**重新考虑条件：** 如果任务出现大量无法预设的只读调查步骤，可以在草稿之前增加受限 Agent；审批与提交边界仍保留。

## ADR 002：第一版选择什么检索方式？

### 可复制模板

```text
标题：为［资料与查询类型］选择［检索方案］
状态：
语料与任务：语言、文档规模、更新频率、权限条件。
质量目标：所需证据类型、拒答规则、关键切片。
备选：关键词、稠密向量、混合、直接长上下文。
决定：索引、分词、排序、阈值与版本规则。
证据：同一数据与预算下的逐题比较；失败样本。
代价：延迟、成本、部署、数据治理。
迁移条件：什么错误比例或负载触发升级？
验证：开发集选择策略、固定测试、引用检查。
```

### 已写示例：透明词项基线优先

**状态：** 已接受于离线检索实验。

**上下文：** 语料很小、使用合成英文、无需外部服务；教学目标是理解证据和阈值取舍。中文与语义改写覆盖属于后续扩展。

**备选：** 词项匹配；embedding 加向量检索；直接把全部语料发给模型。后两者可扩展能力，但会增加调用、计费或模型行为因素，不利于首先隔离检索问题。

**决定：** 使用去停用词后的查询词项覆盖分数，按租户先过滤，再取 top-1 原文；同时保留阈值 0 与 0.6 的结果。

**证据：** 8 道可见测试中，严格阈值将不可回答拒答从 2/4 改为 4/4，同时可回答命中从 4/4 降为 3/4。该结果只支持“当前样本存在此取舍”，不证明 0.6 是最优阈值。

**代价：** 同义表达、中文和多跳证据能力弱。**迁移条件：** 若新增的独立查询集显示词面差异是主要失败来源，就评测稠密或混合检索；仍保留词项基线和相同权限测试。

## ADR 003：如何持久化写入和重放结果？

### 可复制模板

```text
标题：选择［事务／outbox／其他机制］保证［具体边界］一致性
状态：
副作用边界：哪些写入在同一数据库，哪些在外部服务？
故障假设：崩溃、响应丢失、重复提交、并发和撤权。
备选：结果内存缓存、本地事务、分布式事务、outbox。
决定：原子提交内容、幂等键作用域、冲突与保留契约。
保证：可证明的范围，明确不能保证的范围。
后果：吞吐、恢复、存储和运维成本。
验证：逐个崩溃点、并发测试、下游重复测试。
迁移条件：何时更换存储或增加下游协议？
```

### 已写示例：本地工单与去重记录同事务

**状态：** 已接受于 SQLite 实验；外部工单服务采用另一份提议。

**上下文：** 工单与执行记录都在同一 SQLite 数据库中。故障包括批准后修改、写入一半失败和并发重试。

**备选：** 进程内字典缓存结果；先写工单后单独保存结果；同一个事务保存工单、去重记录与状态。前两者在重启或中间崩溃时无法保持要求的不变量。

**决定：** 使用显式本地写事务、唯一约束与 `(tenant, idempotency_key)` 记录，保存原始提交结果。同键异请求拒绝；提交后用原键重放。

**保证：** 在此数据库边界内，副作用和去重记录一起提交或一起回滚；重连后能查到状态。调用者认证和外部服务一致性不在当前保证内。

**后果：** SQLite 写入并发受限，busy 超时需要处理；仍需备份和存储生命周期。审批令牌当前是本地演示值，不应直接暴露到公网接口。

**验证：** `test_effect_and_dedup_record_roll_back_together` 与 `test_concurrent_retries_create_one_ticket` 检查关键故障；正常 demo 不能替代这些测试。

**迁移条件：** 写操作移到外部工单系统时，新增 outbox 与下游幂等契约，并测试响应丢失和对账。更换数据库只解决一部分吞吐问题，不会自动提供跨服务恰好一次。

## 评审时只问三件事

约束是否明确？证据是否支持这个决定？失败时是否知道改哪里？如果一份 ADR 只有“某技术流行、可扩展、性能好”，还没有记录一个可评审的决定。
