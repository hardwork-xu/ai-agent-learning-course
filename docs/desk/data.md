# CaseDesk 数据、版本与评测

CaseDesk 处理客服人员已有的资料，并把问答草稿交给有权限的人审核。演示语料是**原创合成材料**，不是任何真实商家的政策或客户记录。它适合练习文档工程与失败分析；是否能减少真实团队的处理时间，需要另做经授权的试点。

## 从原始文件到可引用证据

原始材料保存在 [`documents/`](../../src/agentlab/desk/documents/)。8 份 Markdown 共 6,187 个字符，按标题切成 37 个分块，其中一份历史活动资料默认撤回；当前索引有 7 份文档、33 个分块。字符数不是 token 数。

| 材料 | 内容与使用场景 |
|---|---|
| 退款受理与审核手册 | 材料是否齐全、7 个工作日审核、例外、状态与重复申请 |
| 支付通道结算与进度排查 | 银行卡与钱包不同期限、时间起点、敏感资料、超时升级 |
| 账号恢复与组织权限操作指南 | 一次性重置链接、SSO、角色变更、请求限制 |
| 订阅取消、账单与发票说明 | 月付与年付的条件差异、缺项、人工核算、发票红冲 |
| 数据导出交付与延迟处理指南 | 6 小时标准交付、24 小时下载链接、快照、范围与权限 |
| 支持事件升级与交接手册 | 影响范围、事件分级、交接材料与不可信数据 |
| 已撤回的春季试点活动说明 | 与现行规则矛盾的历史特例，用于验证撤回和旧引用失效 |
| 原始客户留言：退款排查样本 | 同时包含正常问题和恶意指令，故意保留在活动索引中 |

每份正文包含适用条件、例外和操作上下文。导入时不把正文预先变成“问题 → 标准答案”表，也没有根据评测题维护同义词别名。它仍是小规模合成语料：目前没有 PDF 表格、OCR、多语言合同或百万分块检索证据。

来源清单与文件对应关系见 [`manifest.json`](../../src/agentlab/desk/documents/manifest.json)。文本由课程贡献者原创，按仓库 MIT 许可提供；`urn:casedesk:demo:*` 表示仓库内来源标识，不是假造的外部网站。不要把真实客户资料直接替换进公开仓库。

## 切块与检索的明确边界

导入接受 Markdown 或纯文本，不联网抓取。解析器识别围栏代码块之外的 ATX 标题，保留完整标题路径；正文先按段落组织，超过上限再寻找后半段的句界，仍无法分割时按字符截断。单块最多 1,000 个字符，没有隐含的模型分词或语义切块。标题存于元数据，引用中的 `quote` 必须来自当前分块的正文 `text`。

索引词来自 NFKC 归一化后的拉丁词和相邻汉字二元组；标题、标题路径与正文一起建立词频。检索使用 BM25，`k1=1.2`、`b=0.75`，只返回正分数结果。每次先按租户和活动版本筛选，再计算文档频率与平均长度，避免另一租户的内容影响排名。它没有向量索引、重排器或语义可回答性判断；问题含有共同词语时，无答案也可能得到高排名。

这是可核查的 SQLite 基线。检索会读取该租户的活动分块词频，在 Python 中评分；单租户文档上限 500、单次正文上限 128,000 字符、单文档最多 600 块、返回最多 20 块。**这些输入上限不是性能承诺。** 在接近上限或高并发条件下，应根据真实规模压测，并考虑倒排索引或检索服务，而不是沿用小语料的毫秒数。

## 更新、撤回与审批失效

`KnowledgeStore.ingest` 是增量文档更新：不重建其他文档，每个版本保留不可变的正文、来源和许可。版本 SHA-256 包含租户、文档标识、上个版本、内容、元数据及活动状态；它是版本沿革的内容地址，不只是对正文求哈希。这样“撤回后再导入相同原文”也有新的版本，旧审批不能自动恢复。

```python
from agentlab.desk.knowledge import KnowledgeStore

knowledge = KnowledgeStore("var/knowledge.db")
first = knowledge.ingest(
    tenant="demo", document_id="policy", title="处理规则",
    content="# 处理规则\n\n## 期限\n\n受理后2个工作日回复。",
    source="urn:example:policy", license="MIT",
)
updated = knowledge.ingest(
    tenant="demo", document_id="policy", title="处理规则",
    content="# 处理规则\n\n## 期限\n\n受理后3个工作日回复。",
    source="urn:example:policy", license="MIT",
    expected_revision=first["revision"],
)
withdrawn = knowledge.withdraw(
    tenant="demo", document_id="policy",
    expected_revision=updated["revision"],
)
```

新建已有标识而没有 `expected_revision` 会冲突；两个编辑者使用同一旧版本同时保存，只有一个成功。当前版本内容、标题、来源与许可完全相同，且期望版本正确时，重复导入返回原版本。撤回创建墓碑版本；正常 `get` 与 `search` 只返回活动的当前版本。历史仍在 SQLite 中，**撤回不是物理删除**，有隐私删除义务的部署需要另外定义保留和清理策略。

写入使用 SQLite `BEGIN IMMEDIATE`，索引变更与当前版本指针同事务提交。`validation_guard()` 在复验引用和提交票据期间持有知识库写锁；调用顺序固定为“知识库 → 工单库”，防止检查完来源后，文档恰好在副作用发生前被撤回。它不把两个数据库写入伪装成一个分布式事务。文件系统损坏、磁盘配额、跨机器扩容也不在此保证范围内。

`seed_demo(tenant)` 只在明确调用时导入样例；重复调用跳过已有文档，不覆盖维护者更新，也不复活撤回文档。导入八份样例是逐文档事务，发生错误时可重试跳过已完成项，不承诺全批次原子性。

## 可重复的检索诊断

```bash
python -m agentlab.desk.evaluate --output work/desk-retrieval.json
python -m agentlab.desk.evaluate --split challenge --output work/desk-challenge.json
```

默认在临时 SQLite 中显式导入合成样例，结束后清理。`--database var/knowledge.db --tenant demo` 可检查已有索引，不自动插入样例。报告保存数据哈希、实现文件哈希、当前索引版本、每题结果和所有失败，不设置“通过率达到多少才输出”的筛选。

[`tasks.json`](../../src/agentlab/desk/documents/tasks.json) 包含 24 个公开任务、35 项必需证据标签：

- 10 题 calibration：退款审核、支付通道、账号恢复及缺失资料。
- 14 题 challenge：订阅、发票、导出、跨阶段、事件分级、日历缺项、注入和撤回。
- 任务族只归一个划分；多阶段题仍复用 calibration 的源文档。全部题目随实现共同编写，**challenge 不等于未见数据、盲测或独立评审**。

比较只改变返回上限 `k=1` 与 `k=5`，两者使用同一索引、问题、分词、BM25 参数与正分数门槛；不会给某个基线偷偷关闭检索门槛，也不会按标准答案重排。

| 指标 | top 1 | top 5 |
|---|---:|---:|
| 全部必需证据均取回的题目 | 18/22 | 20/22 |
| 单项必需证据取回 | 29/35 | 32/35 |
| 无依据问题仍被检索放行 | 2/2 | 2/2 |
| 实际取回恶意段落的题目 | 2/24 | 13/24 |
| 取回正文总字符数 | 4,806 | 21,469 |

逐题结果与当前知识库、数据及实现摘要见[已保存的实测报告](../../data/desk/retrieval-diagnostic.json)。这是当前原创语料的诊断结果，不是模型回答准确率。`cal-10` 和 `cha-12` 没有相应政策，但关键词命中仍存在。`cha-08` 的双阶段问题和 `cha-09` 的跨文档交接，在 top 5 下仍遗漏部分证据。多取证据提高覆盖率，同时增加阅读量与恶意内容曝光。报告保留这四个失败，不能通过删题或改标签制造全对结果。

“全证据取回”的分母为有证据标签的 22 题；没有依据的 2 题单列。`extra_document_hits` 仅表示命中文档不在必需文档集合，不能等同于所有额外文本都无关。检索器没有执行生成、人审或工具副作用，所以报告中 `task_completion`、`answer_correctness`、`unsafe_effects`、`human_review_burden` 都是 `null`，不能用 20/22 代替这些指标。

## 真实候选与任务质量怎样验收

实际运行模型或固定流程后，可把结果整理为 JSON 数组，每项包含任务 `id`、`answer`、`citations`（`id/revision/quote`），以及可选的 `state`、`latency_ms`、`usage`，交给 `--predictions`。这个入口只核查当前引用和必需引文覆盖，缺失题不会从分母消失，重复题和未知题会拒绝。供模型实验调用的 `evaluate_predictions(..., task_ids=[...])` 可以预先明确子集，报告会列出选中编号、未选数量和选择摘要；选中但未执行的题仍保留为缺失，不把子集包装成盲测。自报状态、耗时和用量会明确标为未交叉核验；过时版本、其他租户和编造引文不能通过引用检查。

真实项目验收还需要逐题检查以下记录，不能由引用检查代替：

| 验收项 | 需要的证据 |
|---|---|
| 回答完整且条件正确 | 问题要求、支持片段、答案逐项比对；真实审核记录，或明确标注维护者审查 |
| 缺信息时补问 | 缺失字段、补问内容、用户补充后的续执行记录 |
| 多步任务有收益 | 在同题和同授权下比较固定流程与模型规划，记录失败、额外工具调用和审核成本 |
| 不可信材料进入上下文 | 工具观察中确实含攻击负载；不能用预先过滤替代模型接触测试 |
| 没有越权副作用 | 工具提案、网关拒绝、最终租户/票据/outbox/下游效果的实际检查 |
| 人审负担 | 审核人实际阅读和修改耗时、需要改的事实或条件、退回原因；不要由字符数推算 |

攻击样例会要求改租户、读取另一组织案例、泄露令牌及绕过审批。它能被检索到是测试设计的一部分，并不自动说明模型已失败。反过来，模型没有生成危险文字也不证明服务安全；授权和导出边界仍须用运行时的反例测试验证。
