# 面向大学生的价值验收

[学习实验](learning-lab.md) · [真人试学流程](../teaching/pilot.md) · [岗位能力映射](../job-readiness.md)

这个仓库首先是一门能运行、能检验的工程课程。潜在使用者是准备 Agent 应用、AI 后端或相关实习的大学生。CaseDesk 提供完整案例，让学生在持久化状态、数据版本、审核和故障里练习；它不需要伪造企业客户来成为作品集，也不能替学生完成独立成果。

## 读者应该获得的具体结果

| 初始困难 | 课程提供什么 | 怎样验收 |
| --- | --- | --- |
| 名词都见过，不知道先学什么 | 先修诊断、分阶段练习、代码阅读路径 | 能独立完成先修题，解释一次失败 |
| 示例能跑，但换业务不会改 | 原始资料导入、完整应用、四轮迁移实验 | 在新场景保留权限和恢复契约 |
| 简历写了 Agent，项目经不起追问 | 12 个原创深挖场景、故障记录和答辩流程 | 现场修改约束并指出受影响边界 |
| 只有成功截图，没有可信测量 | 配置固定的对照、完整失败题、真实模型轨迹 | 能区分引用检查、任务质量、教学结果 |
| 很难判断是否值得继续投入 | 独立试学和明确退出条件 | 记录完成率、求助、迁移和持续使用 |

## 商业价值如何得到证据

公开可读、运行稳定、有完整内容，只能说明具备交付基础。真实需求、持续使用和付费意愿要由学生行为验证。当前没有已核验的收入、企业采用或就业提升数据；不能将自动测试通过换算成这些指标。

第一轮试学可以招募自愿参加的学生，按[既有试学表](../teaching/pilot.md)记录匿名编号、先修水平和帮助次数。参与者不需要提供真实姓名、学校、账号或简历。先完成参考任务，再换业务、资料与约束，观察是否独立迁移。只会复制运行的参与者不能计入“独立完成”。

建议分别记录以下四组数据，不合成一个营销分数：

- **可进入性：** 环境搭建完成数 / 尝试人数，首次任务完成时间，安装失败类型。
- **能力变化：** 前测与后测使用不同题目；记录独立完成、提示后完成、未完成；保留迁移任务结果。
- **持续使用：** 自愿回访时是否继续修改项目、是否能再次解释设计；不把 star 数当学习收益。
- **需求与支付：** 询问最有帮助和最费解的环节；若后续提供代码评审、答辩陪练或实训服务，单独确认服务内容与真实购买，不把“有兴趣”写成订单。

可能的服务形态是配套讲解、代码评审或小班实践，但仓库当前没有提供收费承诺、付费合同、就业保证或平台代投。任何商业化都应先确认交付能力、授权和真实需求。没有试学数据时，学习收益与付费意愿保持待验证；可以并行修复已复现的产品问题、改善独立练习与部署，但继续增加术语和题量不能补上真实使用证据。

## 面试与简历的表达边界

可用的表达结构是“基于公开课程完成独立变化 → 为什么需要 → 如何实现 → 对照结果 → 尚存限制”。例如，只有实际完成并测量了租户公平调度，才能写该项；填写自己实测的吞吐和拒绝分布，保留机器与规模条件，不能复制参考报告中的数字。

面试官追问时展示需求、关键提交、故障复现和逐题报告。录用受基础、岗位匹配、沟通和招聘条件影响；仓库帮助准备和证明能力，不能把学习完成称作拿到大厂职位。
