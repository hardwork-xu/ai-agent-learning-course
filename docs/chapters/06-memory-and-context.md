# 06｜记忆与上下文：决定这一次究竟让模型看见什么

[上一章](05-retrieval.md) · [首页](../../README.md) · [下一章](07-planning-and-workflows.md)

**本章目标：**计算上下文预算，设计可更新、可删除、可追溯的记忆，避免把摘要当作事实源。

## 三种状态不要混放

| 类别 | 示例 | 合适的位置 |
| --- | --- | --- |
| 工作状态 | 当前步骤、待澄清字段、已完成工具调用 | 结构化任务状态 |
| 会话历史 | 用户原文、工具原始返回 | 受控事件记录 |
| 长期记忆 | 经确认的偏好、跨会话可复用事实 | 有权限和生命周期的存储 |

模型上下文只是本次输入，不是数据库。[MemGPT](https://arxiv.org/abs/2310.08560)探索分层记忆与上下文管理，但“外部存储很大”不等于“每次推理能够可靠使用所有历史”。

结构化工作状态尤其不应只藏在摘要里。例如 `approval_status="pending"` 应是程序字段；摘要误写成“已确认”时，程序仍不能执行提交。数据库事实、用户原话、模型推断也需要分开存放。

## 先给输出和工具结果留空间

设总窗口为 $W$，指令、工具说明、历史、检索证据分别占 $S,T,H,R$，预留输出预算为 $O$，安全余量为 $M$：

$$
S+T+H+R+O+M\le W
$$

具体 API 对输出、推理 token 和窗口的计数方式可能不同，应用应遵循实际接口。下面仅用假设窗口演示预算：

| 部分 | token 数 |
| --- | ---: |
| 总窗口 $W$ | 16,000 |
| 指令 $S$ | 1,000 |
| 工具说明 $T$ | 2,000 |
| 必要历史 $H$ | 3,000 |
| 输出 $O$ | 2,000 |
| 余量 $M$ | 1,000 |
| 可供证据的剩余预算 $R$ | 7,000 |

如果下一次工具调用可能返回 10,000 token，不能只在调用前看“窗口还没满”。应限制返回条数、分页读取、按字段裁剪，或把完整结果保存在外部，仅传入索引与摘要。

## 裁剪应保留决策所需信息

一个可实现的优先级是：固定约束与当前目标、最近用户修正、当前结构化状态、直接相关证据、必要错误结果，最后才是旧的过程叙述。已经成功读过但不再相关的大段文档通常可以移出上下文；原始记录仍保留供追溯。

摘要会压缩，也会丢失。应让摘要携带证据 ID、时间和不确定性，而不是只保存一句流畅结论：

```json
{
  "fact": "申请计划借用相机",
  "source_event": "event-12",
  "observed_at": "2026-01-10T09:00:00Z",
  "valid_until": null,
  "status": "user_stated",
  "open_questions": ["具体型号", "开始日期"]
}
```

这是合成示例。若用户后来改借三脚架，应更新事实并保留替代关系，不能简单把两条都当作当前意图。一次性任务信息也不应自动升级为永久偏好。

[Lost in the Middle](https://arxiv.org/abs/2307.03172)在其测试设置中发现了与证据位置相关的性能差异。它提醒工程师测试信息位置的影响，但不能证明所有现代模型都具有相同曲线。

## 长期记忆的四个写入问题

写入前明确：来源是否可信；是否值得跨会话保留；有效期多长；谁可以读取、更正和删除。嵌入向量、摘要、检索缓存和备份都属于数据副本，不能只删原始文本后就宣称“已遗忘”。

记忆检索需要时间条件。“去年借过的设备”与“现在优先使用的设备”不是同一个查询。新事实未必永远覆盖旧事实：前者可能是一次事件，后者是当前偏好，应该存成不同类型。

[LongMemEval](https://arxiv.org/abs/2410.10813)把信息提取、跨会话推理、时间推理、知识更新和弃答纳入评测。项目可以借用这些测试维度，使用自行构造的合成会话，避免公开真实聊天记录。

## 动手练习与答案

会话先说“这次用相机 A”，后来改成“改用 B，之前的不要了”。压缩摘要只保留“讨论过相机 A 和 B”。指出问题并设计测试。

**参考答案：**摘要丢失了时间顺序、替代关系与当前选择。结构化状态应保存 `selected_device=B`，A 标为已取消，来源分别指向两个事件。测试应在压缩前后询问当前选择，并尝试生成预约草稿；两次都只能使用 B。

再加入“历史上考虑过哪些设备”的问题，正确答案应允许提及 A 与 B。这能检测系统是否为了避免旧信息干扰而误删历史。

**自评标准（4 分）：**当前状态正确 1 分；原始证据可追溯 1 分；历史查询仍正确 1 分；删除与权限边界明确 1 分。

## 面试追问

**“向量数据库就是 Agent 记忆吗？”** 它可以是检索存储的一部分，但还缺写入策略、时间语义、更新冲突、权限、删除和任务状态。只做相似度搜索无法完整实现这些行为。

**“上下文压缩怎么评价？”** 在同一组后续任务上比较答案、动作和关键约束是否保持，另测压缩比和成本。摘要读起来顺畅不是通过标准。
