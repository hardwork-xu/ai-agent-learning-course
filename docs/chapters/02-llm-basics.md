# 02｜模型基础：理解接口背后的概率与成本

[上一章](01-foundations.md) · [首页](../../README.md) · [下一章](03-prompts-and-structured-output.md)

**本章目标：**解释 token、注意力、上下文、采样和训练方式对 Agent 的实际影响。先修要求：向量、矩阵乘法、条件概率。

## 模型在预测什么

自回归语言模型把文本分成 token，并按条件概率逐步生成：

$$
P(x_1,\ldots,x_n)=\prod_{t=1}^{n}P(x_t\mid x_{<t})
$$

token 不等于汉字或英文单词。中文、代码、数字和特殊符号的切分方式取决于 tokenizer；预算应使用所选模型的计数方式，不能把“字数 × 固定系数”当作精确值。

预训练的一个常见目标是最小化负对数似然：

$$
\mathcal L=-\sum_t\log P_\theta(x_t\mid x_{<t})
$$

它鼓励模型预测训练文本中的下一个 token。这个目标本身不等于“所有输出都真实”，也不等于“已经执行了工具”。因此，“语气很确定”“解释很详细”不能充当事实校验。

## 注意力与上下文

Transformer 中常见的缩放点积注意力为：

$$
\mathrm{Attention}(Q,K,V)=
\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V
$$

$Q$ 表示当前位置用于匹配的查询，$K$ 表示可匹配的键，$V$ 是聚合的信息；因果掩码 $M$ 阻止生成位置看见未来 token。原始架构及公式见 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)。

对于长度 $n$、头维度 $d_k$ 的常规稠密注意力，计算分数矩阵需要 $O(n^2d_k)$ 运算。高效内核能减少中间数据读写，不能据此推断所有注意力计算都变成线性复杂度。不同架构也可能使用不同注意力机制，不能把这个结论无条件推广。

**Prefill** 处理输入上下文；**decode** 逐步生成输出。KV cache 保存已处理 token 的键和值，避免每步重新计算它们。它通常减少重复工作，却会占用显存；长上下文和高并发会一起推高缓存需求。KV cache 也不是跨会话的业务记忆。

## 温度与“可信度”无关

给定 logits $z_i$ 和温度 $T>0$：

$$
p_i=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}
$$

温度较低通常使分布更集中；较高则更分散。可直接运行这个小实验：

```python
from math import exp

def probabilities(logits, temperature):
    scaled = [x / temperature for x in logits]
    peak = max(scaled)
    weights = [exp(x - peak) for x in scaled]
    total = sum(weights)
    return [round(x / total, 3) for x in weights]

print(probabilities([2, 1, 0], 1.0))
print(probabilities([2, 1, 0], 0.5))
```

结果分别约为 `[0.665, 0.245, 0.090]` 和 `[0.867, 0.117, 0.016]`。最可能的 token 更占优势，但如果它代表一个错误答案，降低温度只会让错误更稳定。实际 API 的采样能力和参数支持应以所选模型文档为准。

## 四种改善方法解决不同问题

| 方法 | 改变什么 | 适合的问题 | 不会自动解决 |
| --- | --- | --- | --- |
| Prompt / few-shot | 当前调用的条件信息 | 格式、任务边界、示例 | 缺失知识与权限 |
| RAG | 提供外部证据 | 可更新的领域资料 | 检索不到或检索错 |
| SFT | 用示范数据更新权重 | 稳定的输出方式和技能 | 无依据的事实正确性 |
| RL | 根据奖励优化策略 | 有可靠反馈的决策 | 奖励与真实目标错位 |

RAG 的经典工作把检索模块与生成模型结合，见 [RAG 论文](https://arxiv.org/abs/2005.11401)。日常工程里的“RAG”范围更广，不能把所有检索流水线都说成完整复现该论文。

还应区分 embedding 模型与生成模型：前者通常把文本映射成可比较的向量，后者生成序列。相似度高表示在某种表示空间中接近，不等于两句话互相蕴含，更不代表数值、日期和权限一致。

## 动手练习与答案

现有知识问答系统把 20 页文档全部放进上下文，回答慢且偶尔漏掉限制条款。有人建议温度设为 0，再换更大的上下文窗口。给出排查顺序。

**参考答案：**先冻结一批问题和正确证据；检查文档提取是否完整，再看关键证据是否进入输入；控制位置和无关内容比例，比较检索后输入与全文输入；记录延迟、成本和答案依据。最后才比较模型或窗口。低温度无法补回丢失条款，大窗口也不保证有效利用所有位置。

**自评标准：**能区分输入缺失、上下文利用失败和生成错误；至少提出一个只改变单一因素的实验；没有把 token 概率解释为答案置信度。

## 面试追问

**“为什么长上下文仍然需要 RAG？”** 因为容量、查找能力、证据更新、权限和成本是不同问题。若资料很小且访问边界统一，全文输入也可能是更简单的基线；选择应由同一测试集上的质量和成本决定。

**“为什么不能只看参数量选模型？”** 工具调用、结构化输出、领域数据、上下文利用和服务延迟都影响系统表现。用任务级实验选模型，比单一规格更有说服力。
