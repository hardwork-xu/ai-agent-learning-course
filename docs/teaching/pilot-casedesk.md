[试学原则](pilot.md) · [主持与记录表](../templates/casedesk-pilot-record.md) · [先修诊断](../prerequisites.md) · [CaseDesk 入口](../desk/README.md)

**这是待执行的安排，没有参加人数或学习效果结果。** 第一批建议邀请 3–5 位自愿参加的大学生，分别观察，不用组内讨论代替个人尝试。人数是招募建议，未招到或中途退出都如实记录。第一轮回答三个问题：能否找到合适起点、能否完成一个小任务、隔几天能否处理新的约束。它不验收整门课程，更不预测录用结果。

## 组织者在邀请后准备什么

1. **冻结材料。** 按下方方法获取课程候选分支，选一个完成软件检查的提交；在干净的课程副本记录 `git rev-parse HEAD` 和 `git status --short`。发该提交的 GitHub 文件或压缩包链接，保留提交号。学生使用压缩包时，由组织者提供提交号；不要求其运行 Git 才能参与。中途修教材要记新版本，旧记录不改写成新版结果。
2. **先试运行。** 在测试用副本按 [CaseDesk 启动说明](../desk/README.md)安装，再运行 `python scripts/smoke_desk.py`。退出 0 才表示这次软件流程检查通过；它没有真人参与，不能填入学生成绩。只做基础路线时，确认 [起始文件](../../exercises/starter.py)可加载，未修改时诊断应为 `0/9 checks passed`、退出 1。
3. **准备独立环境。** 每位学生使用自己的课程副本和合成工作区，不共用数据库或 token。首次 CaseDesk 用“直接检索”，按入口说明在本机初始化；不接入真实业务资料。组织者先在自己电脑练一次角色切换和停止服务。
4. **准备一张记录表。** 将[模板](../templates/casedesk-pilot-record.md)复制到本地 `work/`，填匿名代号与版本。事先说明会记录哪些行为、谁能看、保留多久；建议原始观察笔记在本轮修订复验结束后 30 天内删除。是否允许匿名汇总发布单独询问，未答复按不允许处理。
5. **约定帮助方式。** 一位组织者同时重点观察一位学生。若只能组织小组活动，每人仍独立写预测、操作和解释；记录同伴帮助。聊天或会议工具的身份资料不抄入学习记录，不开启录制。

学生首次遇到环境问题也是结果。不要让组织者事先安装好所有内容，再把安装耗时记成零。提前完成的准备单独计时；未计时写“未知”。安装依赖需要访问包索引；网络受限时可以转基础路线，将工作台安装记为未完成。

### 获取本轮材料，避免拿到旧版

这轮课程更新目前位于 [草稿 PR 1](https://github.com/hardwork-xu/ai-agent-learning-course/pull/1) 的 [course/application-career-path 分支](https://github.com/hardwork-xu/ai-agent-learning-course/tree/course/application-career-path)。不要默认下载 `main`，否则可能找不到 CaseDesk。使用 Git 时，在父目录运行下面命令；目标目录必须尚不存在：

```bash
git clone --branch course/application-career-path --single-branch https://github.com/hardwork-xu/ai-agent-learning-course.git ai-agent-course-pilot
cd ai-agent-course-pilot
git rev-parse HEAD
```

组织者与学生核对输出是否是约定提交。分支会继续更新；输出不同就先停下来，由组织者提供**原定提交的文件链接或压缩包**，不要临时更换材料却沿用旧记录。已有作业保留原目录，不执行重置或覆盖。使用 ZIP 时，组织者从约定提交页面提供对应压缩包及完整提交号；解压后在包含 `pyproject.toml` 的根目录执行后续命令，并将该提交号记入表格。ZIP 中没有 `.git`，无需运行 `git rev-parse HEAD`。

## 按实际起点选路线

可以在约定时间前自愿尝试 [先修诊断](../prerequisites.md)，保留自己的答案与失败输出。不要求为参加活动提前做完所有课程；未做就是“未测”，不是“能力不足”。会面时核对自己完成的部分，并口头解释一个输入、错误或事务反例。

| 路线 | 适合的实际表现 | 首场只验收什么 |
| --- | --- | --- |
| A：先修与工具，60 分钟 | 还不熟函数／字典，或 JSON、HTTP、SQL 有缺口，或尚未做应用基础 | 选择一个缺口完成一次尝试与修正；已有 Python 基础者做第一关只读工具 |
| B：CaseDesk，90 分钟 | 能独立完成先修诊断并解释反例；已做基础练习与项目 04–05，或能用自己的项目展示对应的 HTTP、身份和事务能力 | 跑通一条合成任务，解释证据与审核，独立检查一个权限变式 |

路线 B 的替代证据只需现场说明和合成演示，不回收私人项目。仅有 `9/9` 或“学过后端”的自报不足以证明应用基础。无法判断时选 A；学生可自愿观看工作台，但观看不记为操作完成。路线 A 的成功标准也不是一小时补齐全部先修。

## 路线 A：60 分钟

| 时间 | 学生做什么 | 组织者记录什么 |
| --- | --- | --- |
| 0–5 分钟 | 确认本次范围、记录方式与可退出 | 匿名代号、版本、同意范围；不填身份信息 |
| 5–15 分钟 | 按先修页创建自己的答案文件，运行诊断 | 环境是否可用，实际输出；区分未实现与无法加载 |
| 15–30 分钟 | 选 JSON 校验这一小节；已经会的学生改做 [第一关只读工具](../practice.md#第一关照着数据流实现只读工具) | 首次失败位置、学生自己的猜测、用过的提示 |
| 30–45 分钟 | 保存当前代码，做下方的一项小变式 | 修改前预测、实际改动、结果与帮助；不代写 |
| 45–55 分钟 | 用自己的话解释一条失败为何应被拒绝，再运行一个自己选的输入 | 能解释哪些，哪些仍需提示；未完成不补写为通过 |
| 55–60 分钟 | 简短访谈，选择是否约延迟任务 | 最有用的具体环节、卡点、后续意愿为自报 |

**小变式只选一项。** 做 JSON 的学生先独立判断 `{"units": true}` 与 `{"units": 1}` 是否应同样接受，再在自己的实现上运行、修正；做库存工具的学生在新的合成目录中加入库存为 0 的商品和一个格式合法但不存在的编号，分别预测返回或异常并验证。允许看题目契约与官方文档。已经看过相同反例时，记录“已见”，改用本人尚未尝试的边界；不把公开例题称作盲测。

若前 30 分钟仍无法运行 Python，后半场只修一个环境问题或做纸面追踪；记录“未进入编码任务”，结束时间照常保留。不要延长到学生不得不完成为止。

## 路线 B：90 分钟

| 时间 | 学生做什么 | 组织者记录什么 |
| --- | --- | --- |
| 0–10 分钟 | 确认范围，展示先修结果并解释一个失败 | 实际依据、已见材料、未测项与路线选择 |
| 10–30 分钟 | 按 [入口](../desk/README.md#先跑通一次完整流程)安装、初始化、打开本机页面 | 安装时间、卡点、帮助；提前安装的时间另列 |
| 30–50 分钟 | 用入口问题完成“创建 → 查看原文 → 换审核人修订批准 → 换回申请人提交” | 哪一步独立完成；是否把“预计到账”误写成“已经到账” |
| 50–70 分钟 | 做下方权限小任务 | 先写预测，再操作；保留脱敏状态码与实际状态 |
| 70–80 分钟 | 画出请求、后台任务、审核与工单四段；口头解释 HTTP 202 | 观察到的解释，不能只记录“懂了” |
| 80–90 分钟 | 访谈、决定回访范围、停止自己的服务 | 使用意愿是自报；按 Ctrl-C 停止服务，不删除他人进程 |

**权限小任务给学生的说明：** 新建一条合成任务，等到“待审核”。先预测：同租户的审核人能否取消这条任务？创建者是否可以？参考 [第一轮接口练习](../desk/learning-lab.md#第一轮一条任务从哪里来到哪里去)的本地凭据读取与请求写法，在 `work/` 写一小段检查：先由审核人尝试取消，再读取状态；最后由创建者取消。输出只保留状态码和任务状态，不输出 token。指出服务器在哪一处做决定，并解释“能审核”是否等于“拥有全部操作权限”。

可以复用安全读取凭据的代码，但要记录参考范围；独立性只评价预测、变式与解释，不声称整段请求程序从零独立编写。主持人的预期与帮助记录放在[记录表](../templates/casedesk-pilot-record.md)，不要提前逐项讲答案。

如果安装持续到第 30 分钟仍未完成，停止追赶完整流程：转路线 A 的一个小任务，或结束并记录安装失败。工作台只完成一半也保留原结果。不要让组织者接管鼠标完成后算学生通过，不强制追加模型下载、全部故障演练或租户配额实现。

## 2–7 天后的延迟任务

自愿回访 20–40 分钟，先不重放上次讲解。记录间隔、期间是否练过及看过哪些材料；前者按实际日期，后者是学生自报。先写需求与预测，再操作，最后解释。延迟任务改变一项关键约束，不能仅替换故事名称。

- **A 路线：** 在合成设备库存中加入 `reserved`（已预留数量），可借数量改为 `stock - reserved`。独立实现 `available_units(item)`：输入必须是恰好含 `stock`、`reserved` 的字典，两者为非负真正整数；`reserved > stock` 或其他非法输入抛 `ValueError`，合法时返回可借数量，不修改输入。自己设计正常、全被预留、非法预留三类用例。只评价这个新函数，不要求实现整套借用系统。
- **B 路线：** 在自己的合成工作区创建并批准一条任务，尚未提交时撤回所引用的一份资料。先预测提交和恢复原文后的行为，再按照 [入口第 5–6 步](../desk/README.md#先跑通一次完整流程)验证。解释为何恢复相同正文不应让旧批准自动复活，并定位版本检查。此题用文档步骤验证；如果已提前练过，改选 [第二轮资料实验](../desk/learning-lab.md#第二轮资料变化之后旧答案还能不能用)里的另一个时点，明确记录已见范围。

没有回访、超时或中途停止分别记录，不把缺失算成功或给它补造零分。回访显示能迁移，只能支持该学生在该任务、该帮助条件下的观察。

## 可选的作品扩展：另约 2–4 小时

有余力且已完成基础路线的学生，可在数次学习后选择 [租户配额任务](../desk/tenant-capacity-lab.md)。2–4 小时是一次独立尝试的时间预算，**不是完整完成时限**；可只交需求、原版反例和一项可运行的顺序场景，其他项保留未完成。

不要在首场承诺做出完整并发扩展。继续完成时按任务表逐项检查，尤其是幂等重放、重新批准与真实并发；再用 [作品证据清单](../desk/student-value.md#把独立改动整理成可审查作品)区分课程参考与个人贡献。现有的 [申请撤回任务](learner-task.md)属于另一项较完整的应用迁移，仍按它自己的先修与 [评审要求](reviewer.md)进行，不混作首场快速题。

## 怎样判断值得修、值得继续

访谈只围绕具体行为，每次选三问即可：

1. 今天原本想学会什么？实际在哪一步更接近了，哪一步没有？
2. 最近一次尝试学同类内容，用了什么材料或办法？这次多了什么，少了什么？
3. 哪个卡点消耗最多时间？你当时希望页面或教材给出什么信息？
4. 如果下周继续，你最想完成哪一个任务？是什么可能让你不再继续？
5. 需要额外帮助时，你会选自己查资料、同伴讨论、代码评审还是现场讲解？为什么？

不要问“这个项目是不是很有用”“你愿不愿意为高质量课程付费”来制造赞同。口头愿意继续是自报；回访时实际继续修改才是行为证据。付费需求、真实购买、就业改善仍保持未知，本轮不收款，也不据此宣布商业验证成功。

以下是小规模修订的行动规则，不是统计显著性门槛：

| 观察到什么 | 下一步 | 修复后怎样复验 |
| --- | --- | --- |
| 出现凭据被要求公开、真实数据外送或访问越界 | 立即暂停受影响步骤，保存不含敏感内容的最小复现 | 修正说明／程序；先做边界检查，再恢复试学 |
| 一人同一步独立尝试约 8 分钟没有新进展，或主动求助 | 问其当前判断，提供最低一级帮助；本人可继续或退出 | 记录具体帮助；换小变式检查能否自行推进 |
| 两人出现相同卡点，或一个软件故障可稳定复现 | 优先修教材入口、错误说明或程序，记录旧版本失败 | 软件检查通过后，请尚未见修复解法者只按新材料操作；原参与者复测另记为已见 |
| 能复制流程，但不能解释 202、角色或引用 | 暂不升级难度，补一张数据流或一个反例 | 换输入重新解释与验证，不能只重复背原句 |
| 首场完成、延迟任务未完成 | 保留两次结果，定位遗忘、资料导航或迁移缺口 | 下一次只改变一个教学环节，记录任务是否仍可比较 |

汇总时分开写：尝试人数、完成数、退出／缺失、帮助分布、卡点、延迟任务实际参与人数。把路线 A 与 B 分开，不对 3–5 人的小样本做就业或全体学生成功率推断。公开总结须经过单独同意与脱敏检查；没有同意就只在本地修订教材。
