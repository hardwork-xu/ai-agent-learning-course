# 小规模试学：验证学生是否真的学会

[学习路线](../roadmap.md) · [学生任务页](learner-task.md) · [观察者记录](reviewer.md)

**当前状态：已提供试学流程，尚无真人试学结果。** 自动化检查验证教材代码，不能替代学习者观察。不要填入虚构人数、完成时间或通过率。

## 参加者与材料

先找愿意参加的学习者，说明可以随时退出，不要求公开作品或个人信息。区分两种起点：已能编程但未学 Agent 的 CS 学生，以及尚不具备编程基础的学习者。后一组先完成先修诊断，不直接进入应用项目。无需姓名、学校、联系方式、账号、成绩或屏幕录像；用学习者自行选择的随机代号即可。

试学材料为固定版本的仓库、学生任务页和本地记录模板。学习者的源码和记录默认留在其本地。未经额外同意，不把材料上传、放进公开 PR 或发送给模型服务。

## 顺序

1. **开始前：** 记录 Python/HTTP/SQL 的实际诊断结果、教材提交版本和愿意投入的时间；不按身份推断水平。
2. **引导学习：** 完成环境准备、一个有提示的工具练习。观察者记下卡住的位置和提供过的帮助，不代写答案。
3. **独立任务：** 只给 [学生任务页](learner-task.md)。允许查官方 API 文档；是否使用提示或代码生成工具如实记录，不能把有帮助的结果记作独立完成。
4. **延迟迁移：** 下一次学习时换数据和一项关键约束。先保留原实现，再比较修改和测试；不要仅更换名词。
5. **答辩：** 请学习者解释一个失败反例、一次取舍和自己的代码；记录事实，不用总分掩盖实现缺口。
6. **修订：** 按卡点修改教材，再找新的独立任务复验。保留旧版本和修订理由。

## 结果怎么写

使用 [记录模板](../templates/learning-record.md)。分别报告解释、实现、诊断、迁移；记录帮助程度和未完成项。样本很小时只描述观察，不推断所有学生的完成率，更不能推断录用概率。

公开总结只包含获准发布的匿名汇总与必要的合成示例。原始记录、凭据、个人代码和环境路径都不进入本仓库。没有参加者时，本项保持“待验证”，其他软件验收可以继续。
