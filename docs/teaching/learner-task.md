# 独立迁移任务：撤回尚未批准的申请

本页不含参考实现。开始前运行参考服务和学生练习，确认能够解释请求、身份与审批版本。记录仓库版本，在自己的分支实现，先不要阅读观察者评分页。

## 场景

校园服务台已经能够查询制度、生成申请、批准和提交。现在申请人发现自己报错了，希望**撤回尚未批准的申请**。

要求：

- 只有该申请的创建者能够撤回；其他申请人和其他租户不可以。
- 只允许撤回待审批状态；已批准或已提交时返回明确冲突，不能谎称副作用已撤销。
- 请求必须携带调用者看到的版本；过期版本不能撤回新内容。
- 撤回请求带一个稳定的 `withdrawal_key`，绑定创建者、申请、原 expected_version 和请求摘要。首次撤回只有 pending 且版本相符时成功，版本增加一次；之后同键同摘要重放已保存的撤回结果，允许已是撤回状态且调用者携带原版本。每次重放仍先检查当前身份与资源权限。
- 同键异摘要返回冲突；没有可重放记录的新请求继续执行状态和版本检查。重启后仍可查询原撤回结果。
- 撤回后的申请不能继续批准、修改或提交；不要修改旧数据使已经提交的工单消失。
- 错误与日志不暴露令牌或请求正文。

## 交付

1. 在编码前写一页接口与状态转移说明，列出待确认的需求。
2. 实现修改，并编写会在原版本失败、在新版本通过的行为测试。
3. 展示普通成功、错误身份、过期版本、重试和重启五种情况。
4. 保存改动与一条可运行命令，说明哪部分参考了课程，哪部分独立完成。
5. 解释“撤回申请”和“撤销已经发生的业务动作”为什么不同。

完成后由观察者提供第二轮约束。遇到卡点可以请求帮助，但记录帮助内容；诚实记录比把所有项目写成一次通过更有学习价值。
