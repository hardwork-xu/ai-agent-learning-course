逐题结果：[默认组](../../data/model-runs/2026-10-05/dev-default.json)、[较大预算组](../../data/model-runs/2026-10-05/dev-2048.json)、[追加组](../../data/model-runs/2026-10-05/dev-2048-20s.json)。每列的前置拒答、原文发布、待审和运行错误合计为 12 题。退出码 0 表示评测正常跑完，不表示全部回答正确。

较大预算组同时改变了输出上限、单次超时和全组预算，不能据此声称只增加 token 上限就造成全部变化。单次运行也不能估计波动；比较改动时应保持其余条件一致，再重复测量。

追加组使用相同源码快照，命令配置仅将默认组的输出上限改为 2048；但与上一组间隔已超过服务的 `keep_alive=2m`，运行条件仍未完全隔离。首题在约 20 秒时超时，没有取得该次 token 数，应保留 `null`。它证明时间预算也需要检查，不能用于断言增加 token 上限必然使模型变慢。默认组记录的生成 token 合计为 2242，较大预算组为 2581；追加组只能报告已有值及其覆盖的调用数，详见来源记录。

## 三个值得保留的失败

**1. 服务连通，仍可能拿不到完整输出。** 单题检查实际访问了模型，服务器报告输出 token 为 384，适配器记录 `output_budget_exceeded`，命令退出 2。默认 dev 中 `zh-001`、`zh-002`、`zh-003` 也出现同类错误。它们属于输出预算问题，不能写成“没有找到资料”。失败调用已取得的用量仍应保留。

历史版本在这些错误下仍显示“资料不足”，错误分类和用量字段却正确记录了失败。本次已修复提示，明确显示有资料但生成请求未完成；历史 JSON 保持原样，便于对照问题与修复。

**2. 原文真实，严格指标仍可能判为未通过。** 较大预算组的 `zh-001` 正确摘录“审核期限为七个工作日”，同时附上 `refund-review` 和 `refund-arrival` 两项引用。该题预期集合只有 `refund-review`，集合不完全相同，因此 `correct_decision=false`。这不等于已经证明答案存在事实错误，而是暴露了“精确引用集合匹配”这项指标的边界。若增加对冗余引用的容忍度，应单独定义新指标，保留原结果，不能悄悄改分。

**3. 有引用的改写，仍需逐项核对。** `zh-004` 的证据写的是“十四个自然日”，生成草稿变为“14天”。数字相同，但明确的时间限定词被省略。当前机制将其保留在 `generated_draft`，标记 `requires_review`，没有自动发布。这里指出一个应检查的差异，尚不能把待审草稿记为已通过独立人工审核。

严格 7/12 包括 5 道前置拒答和 2 道符合预期引用集合的已发布答案。待审内容不计为通过；较大预算组多发布的 `zh-001` 又未满足集合条件，所以总分没有变化。把这条计算过程解释清楚，比只报一个百分比更有价值。

同一报告中的离线摘录基线为 11/12。在这组短政策问答和严格引用指标上，加入模型没有带来更高分数；它增加了生成改写的能力，也引入了预算、待审和引用选择问题。是否值得引入模型，应结合任务所需能力、人工审核成本和失败后果判断。

## 怎样复现这类实验

先按[中文 RAG 教程](../projects/04-chinese-rag.md)准备 Python 环境和可信的本地 Ollama。要复现本页权重，请从上面的固定官方版本获取 GGUF 并核对 SHA-256；文件不放入 Git。按 [Ollama 的 GGUF 导入说明](https://docs.ollama.com/import)，在权重所在目录创建 `Modelfile`：

```text
FROM ./Qwen3-0.6B-Q8_0.gguf
PARAMETER num_ctx 4096
```

在该目录导入并检查标签：

```bash
ollama create course-qwen3:0.6b-q8_0 -f Modelfile
ollama list
```

回到课程仓库根目录，运行下面三条命令。命令使用单行，便于在 Bash 或 PowerShell 中执行；报告写入自己的 `work/`，不要覆盖仓库保存的历史报告。

```bash
python -m agentlab.rag_eval --mode local --model course-qwen3:0.6b-q8_0 --split dev --repeats 1 --timeout 20 --max-output-tokens 384 --max-model-calls 12 --max-total-seconds 180 --output work/local-dev-default.json
python -m agentlab.rag_eval --mode local --model course-qwen3:0.6b-q8_0 --split dev --repeats 1 --timeout 40 --max-output-tokens 2048 --max-model-calls 12 --max-total-seconds 300 --output work/local-dev-2048.json
python -m agentlab.rag_eval --mode local --model course-qwen3:0.6b-q8_0 --split dev --repeats 1 --timeout 20 --max-output-tokens 2048 --max-model-calls 12 --max-total-seconds 180 --output work/local-dev-2048-20s.json
```

本页历史报告来自 `2083aec`，后来代码或失败文案的修改不会追溯改写报告里的源码摘要。运行新版本时记录自己的提交、模型 digest 和配置；即使温度设为 0，也不要要求不同运行环境逐字重现同一份输出。

单题入口与服务入口现在也支持 `--timeout` 和 `--max-output-tokens`。实际使用 40 秒、2048 token 的[单题结果](../../data/model-runs/2026-10-05/single-configured.json)和[完整 HTTP 流程记录](../../data/model-runs/2026-10-05/actual-model-service.json)已保存：中文物流问题由真实模型返回原文，申请、模拟审核、幂等提交和下游投递完成，重放保持一张工单和一个下游效果。HTTP 客户端等待上限为 55 秒；与模型内部 40 秒预算分别配置。

审核者是测试脚本中的明确角色，不能记成真实人员审核。新入口与提示修改的源码文件摘要保存在来源记录中，和历史 dev 报告的提交分别标识。实验结束后，本次启动的模型服务已停止。

## 这份记录能够证明什么

它证明指定运行时和本地权重执行过真实请求，记录了截断、原文选择与待审草稿。公开 dev 数据已经参与调试，不是未见测试；没有独立真人语义评审，也没有学习者试学。待审仍保持待审，维护者跑通实验不等于学生已经独立掌握。

继续练习时，为运行错误、来源一致性、问题相关性和语义支持分别保留证据。原始结果中不保存内部思考文本，分享报告前检查路径、日志和个人信息。
