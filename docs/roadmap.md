# 学习路线：基础、应用与校招准备

[返回首页](../README.md) · [从这里开始](start-here.md) · [岗位对照](job-readiness.md)

先以 **Agent 应用开发**为主线。进度以可检查的产物决定，不以读完章节或固定周数决定。每段先预测行为、自己实现，再检查失败并解释；已有基础的部分可通过验收后跳过。

## A：把先修知识接起来

| 检查点 | 学什么、做什么 | 返回条件 |
| --- | --- | --- |
| A0 运行环境 | Python 文件、字典、函数、异常、终端与 Git | 能运行自己的函数，看懂异常位置，确认改动范围 |
| A1 接口数据 | [先修诊断](prerequisites.md)中的 JSON 与字段、类型校验 | `json_` 三项通过，解释 bool 与 int 的陷阱 |
| A2 网络与存储 | 同页的 HTTP 决策、SQL 参数绑定与事务 | `http_`、`sql_` 六项通过，展示失败回滚 |
| A3 模型直觉 | [第一章](chapters/01-foundations.md)、数学桥梁、[第二章](chapters/02-llm-basics.md) | 区分下一词预测、工具执行和最终任务结果；手算一个概率与矩阵例子 |

A0 不熟时先补编程。A1–A2 的起始文件不能直接通过，必须运行自己的答案。A3 的训练公式可以分次消化；不要因为尚未学习 GPU 编程而停下应用练习。

## B：从跟做到独立实现

| 检查点 | 交付 | 对照材料 |
| --- | --- | --- |
| B1 只读工具 | 严格校验的库存查询；正常、未知商品、额外字段三个例子 | [渐进练习第一关](practice.md)、第 03–04 章 |
| B2 不完整代码补全 | 自己的整数金额报价工具；类型和总价边界测试 | [渐进练习第二关](practice.md) |
| B3 场景迁移 | 设备借用申请的持久化、冲突拒绝、并发重放与回滚 | [独立迁移任务](../exercises/transfer-task.md)、第 07 章 |
| B4 解释与改需求 | 一次约定的变式实现和失败复盘 | [评审量表](../exercises/reviewer-rubric.md) |

**基础实现验收：** 学生文件的公开检查通过；能不看答案解释一次修复；完成 B4。参考代码的 20 项通过不能代替这一条。B1–B3 只是局部技能，尚不是求职毕业应用。

## C：完成一个可运行的应用项目

这是必修阶段，必须交付实际代码，不能用设计文档代替。课程参考服务帮助理解接口；学生仍需按[毕业项目验收](projects/capstone.md)完成自己的场景与变更，并保存可复现证据。

| 检查点 | 实际产物 | 验收重点 |
| --- | --- | --- |
| C1 中文检索 | [中文 RAG 项目](projects/04-chinese-rag.md)的运行记录、逐题错误分类和一个有证据的改动 | 区分检索相关性、引用支持、答案完整性；不能只报总分 |
| C2 完整服务 | [应用服务](projects/05-service.md)的查询、申请、读取、审批和提交接口 | 认证身份决定租户与角色；不能信任请求自报权限 |
| C3 状态与恢复 | 重复请求、审批版本变化、事务失败和 outbox 恢复演示 | 状态写入与副作用记录一致；确认哪些保证仅限本地模拟 |
| C4 模型与评测 | 自己运行的真实模型结果及离线基线；逐题对照、参数、延迟与使用量可得性 | 没有运行过真实模型时标注未验证，不能把抽取式结果当模型生成质量 |
| C5 运行与交接 | 从新目录启动的说明、配置分离、健康检查、失败定位与恢复记录 | 同伴按说明可复现；本地教学服务不直接暴露公网 |

参考命令如下。先按首页完成课程包安装，并阅读对应项目说明。

```bash
python -m agentlab.rag_eval --output work/zh-evaluation.json
python scripts/smoke_service.py
```

第一条默认是离线抽取式评测；真实本地模型方式与约束见[中文 RAG 教程](projects/04-chinese-rag.md)。第二条运行隔离的真实 HTTP 流程，审批参与者与下游动作使用教学模拟。运行通过只说明参考服务在该场景下的行为，不代表学生写过同样的系统，也不是负载、安全或真实模型质量认证。

**应用验收：** 按[毕业项目](projects/capstone.md)逐项提交；至少保存一个失败、修复前后对照和自己的业务变更。确实缺少模型运行资源时，可以先完成其余项，但 C4 保持未完成状态，不把离线替身包装成模型实测。外网托管不是默认要求，展示的是可复现的本地运行与交接能力。

## D：将项目转为求职证据

1. 按[岗位对照](job-readiness.md)选择实际目标岗位，区分基础要求、加分项与自己尚未覆盖的能力。
2. 完成[计算机基础与编码准备](interview/cs-foundations.md)。Agent 题库不能替代算法、数据库、操作系统、网络与编码能力。
3. 用[作品集模板](templates/portfolio.md)写清问题、自己的工作、实现边界、数据与评测、失败和改进。仅把自己实际完成的部分写为经历。
4. 做一次[模拟面试](interview/mock-interviews.md)，覆盖项目、编码与系统设计。不会的部分回到具体代码和实验补练。
5. 让评审者按[迁移任务](teaching/learner-task.md)和[评审规则](teaching/reviewer.md)增加一个约束，记录独立完成度与所需帮助。

**求职准备验收：** B、C 的必需产物齐全，计算机基础有独立练习记录，能解释项目中的取舍并完成新需求。达到课程验收意味着有可展示、可追问的准备证据，不保证任意公司的笔试、面试或录用结果。

## 扩展方向

完成应用主线后，再按岗位选择第 06 章的上下文策略、第 08 章的多 Agent 对照、第 12 章的研究实验。不要为了展示框架数量把应用拆得更复杂。

算法研究路线另外学习线性代数、概率、机器学习、PyTorch 训练与论文复现；AI Infra 路线另外学习操作系统、并发、分布式、性能分析与推理优化。课程中的概念阅读只是连接点，这两条路线不能用应用主线结课替代。

## 如何安排每周时间

给本周选择一个足够小的检查点，将时间分给阅读、实现、实验和解释。卡住时记录缺项，缩小练习范围，不把“计划花多少小时”当作必须达到的成绩。

小组轮换实现者、评审者和评估者；每个人都要独立通过局部练习和变式。项目分工可以按数据检索、服务流程、评测运行划分，最终共同做接口与恢复验收。试学方法与结果记录见[教学试学方案](teaching/pilot.md)。
