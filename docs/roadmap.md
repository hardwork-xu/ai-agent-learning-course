# 十周学习路线

[返回首页](../README.md) · [准备工作](start-here.md)

按每周约 6–10 小时安排，总时长是规划参考；薄弱的 Python、网络与数据库基础需要另留时间。每周把时间分给阅读、编码、实验和口头解释，不以阅读页数作为进度。

| 周 | 核心内容 | 本周交付 | 自测问题 |
| --- | --- | --- | --- |
| 1 | 第 01–02 章、环境与三个 demo | 一张系统数据流图和一次运行记录 | 哪一步需要模型，哪一步必须由程序保证？ |
| 2 | 第 03–04 章、工具项目 | 新增一个只读工具及异常测试 | JSON 合法为什么仍可能执行错误？ |
| 3 | 第 05 章、检索项目 | 两种检索配置的逐题对照报告 | 失败来自没检索到，还是没正确使用证据？ |
| 4 | 第 06 章、上下文预算 | 一个摘要丢失约束的反例及修复 | 哪些状态不应仅存为自然语言摘要？ |
| 5 | 第 07 章、工单项目 | 重复请求、过期审批和恢复演示 | 超时之后怎样判断能否重试？ |
| 6 | 第 08 章、协议与框架 | 单 Agent 与并行方案的成本设计 | 子任务是否独立，冲突由谁裁决？ |
| 7 | 第 09–10 章 | 测试集说明、攻击用例、错误分类 | 评估分母、权限主体与信任边界分别是什么？ |
| 8 | 第 11 章、毕业项目设计 | API、SLO、监控和故障恢复方案 | 服务排队变长时怎样限制放大效应？ |
| 9 | 第 12 章、研究实验 | 一份有基线和消融的实验记录 | 哪个结果会推翻自己的假设？ |
| 10 | 面试题、模拟面试、项目答辩 | 可复现 README、五分钟演示、设计复盘 | 能否展示失败而不是只展示成功截图？ |

## 三个阶段验收

**基础验收（第 3 周）**：从零画出 Agent 循环，运行工具和检索项目，修改一个行为并解释至少两个失败样例。无法解释模型与执行器的责任分工，应回到第 04 章。

**工程验收（第 7 周）**：对重复请求、跨租户访问和不可信工具结果给出代码层面的阻断证据；用同一评估集比较基线，报告分母和误差来源。仅修改 system prompt 不算完成权限控制。

**求职验收（第 10 周）**：在干净环境复现项目，完成一次 45 分钟模拟面试，并展示一项由实验推动的改动。能说明未实现的生产能力，避免把原型描述成线上系统。

## 两周复习路线

适合已经会写 Python 后端、至少做过一个 LLM 应用的读者。

- 第 1–2 天：Agent、LLM、工具边界；运行并解释工具测试。
- 第 3–4 天：RAG、记忆；手动分析五个检索失败。
- 第 5–6 天：状态机、幂等、权限；复现工单流程。
- 第 7–8 天：评估与成本；生成一份带分母的对照报告。
- 第 9–10 天：系统设计、协议、多 Agent 取舍。
- 第 11–12 天：代码题与第一轮模拟面试。
- 第 13–14 天：补弱项、复跑实验、五分钟项目答辩。

## 小组学习

三人小组可以轮流担任实现者、评审者和评估者。实现者先提交设计与预测；评估者使用预先冻结的测试题；评审者检查证据是否支持结论。每周交换角色，防止一人写完代码，其他人只会讲概念。

毕业项目不要按“一个人负责一个 Agent”机械拆分。更有效的分工通常是数据与检索、工具与流程、评估与服务，最后共同承担接口和验收责任。
