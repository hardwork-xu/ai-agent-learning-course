## 怎样读一条资料

`id + revision + tenant` 标识一个版本。`valid_from` 包含当天，`valid_until` 不包含当天；`null` 表示尚未配置结束日。只有 `approved` 状态且在指定日期有效的资料参与检索。

同一租户、同一 `id` 先选择已经生效且不是 draft 的最新发布版本，再判断它是否有效。最新版本已撤回或已过期时拒绝使用该资料，不会回退到仍未填写结束日的旧版本。撤回版本是逻辑文档的撤销标记；重新启用须发布生效日期更晚的新版本。

所有日期必须使用规范的 `YYYY-MM-DD` 格式。同一资料的两个版本不得具有相同生效日期；存在歧义时直接拒绝加载，避免用 `v9`、`v10` 的字符串顺序猜测新旧。真实文档系统应进一步定义唯一发布序号及发布事务。

`fact_key` 是人工整理的事项标识，如 `refund.review_days`；`value` 是归一化事实值。两个有效资料的同一事项值不同，就标记冲突。这只能发现**已经结构化标注的冲突**，不能自动读懂任意自然语言矛盾。

`aliases` 是人工写出的检索辅助短语。它帮助词法检索处理部分改述，不代表词向量或模型推理能力。增加别名后应重跑全部用例，检查是否引入误召回。

## 怎样读一条题目

- `expected_ids` 与 `expected_facts` 指向预期有效版本和原文；空列表表示应该拒答。
- `slice` 用来分组分析，不用于运行时选择答案。
- `query` 不携带可信租户身份；`tenant` 由应用鉴权结果提供。
- `expected_action` 是本题标注，不发送给模型。模型只接收问题和检索结果。

`zh-041` 特意保留一个失败：问题询问自提点地图坐标，词法检索却找到营业时间。原文引用完全真实，回答仍然不切题。不要修改标注来把这个失败算成成功。

## 如何比较

```bash
python -m agentlab.rag_eval --split dev --output work/zh-dev.json
python -m agentlab.rag_eval --split test --output work/zh-test.json
```

报告同时保留配置、代码、资料、题目哈希和逐题轨迹。默认基线和候选使用同一 BM25，区别是最低词项覆盖率分别为 0 和 0.32。这是用于观察取舍的教学参数；材料和代码编写时已经查看过 test，不存在隐藏测试独立性。

开发新方法时，应先固定一版资料和 dev 配置，再请另一位同学编写新题并封存。记录出题时间、与旧题的差异、标注分歧和解封时间。那批新题才有条件用于评估未见题迁移；仍不能替代真实业务试点。

## 发布结果前

说明模式、运行版本、样本数和分母。`exact_quote_integrity_answered` 只表示已作答项引用了可见原文；切题性看 `relevant_answer_precision`。两个指标不能合并成“可信度”。

`local` 模式还需保留实际模型标签、digest、可获取的服务器版本、token 计数和逐题人工复核。已取得的 token 用量在模型 JSON 损坏或输出截断后仍保留；未知字段保持 `null`。HTTP 替身测试和离线结果不充当真实模型结果。生成草稿里出现的声明也不能自动写进最终答案。
